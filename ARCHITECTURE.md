# Архитектура и правила разработки

Документ описывает, **из чего** и **как** строится расширение. План работ — в [ROADMAP.md](ROADMAP.md).
Если решение меняется, обновляем этот файл и добавляем запись в [журнал решений](#журнал-решений).

---

## 1. Требования, которые определяют архитектуру

| Требование | Что это значит на практике |
|---|---|
| Стабильность | Ошибка в одном запросе/подключении не ломает остальное. Никаких необработанных promise. |
| Скорость | Активация — только по необходимости; драйверы грузятся лениво; таблица виртуализирована; тяжёлая работа не блокирует extension host. |
| Работа во всех форках | Только чистый JS/WASM, без нативных модулей. Только стабильный (не proposed) API VS Code. |
| Безопасность | Пароли — в SecretStorage. Строгий CSP в webview. Значения в SQL — только через параметры или экранирование диалекта. |
| Расширяемость | Новая СУБД = новый драйвер по одному интерфейсу, без правок в UI. |
| Тестируемость | Логика не зависит от `vscode` и тестируется обычными unit-тестами. |

## 2. Стек

| Что | Чем | Почему |

| PostgreSQL | `pg` (+ `pg-cursor`) | Стандарт де-факто, чистый JS. |
| SQLite | `node:sqlite` в `worker_threads` | Встроен в Node редактора с VS Code 1.105, без нативных модулей (D5, D23). |
| SSH (V4) | `ssh2` | Чистый JS. |
| Дальнейшие драйверы | `tedious`, `@clickhouse/client`, `oracledb` (thin), `ioredis`, `mongodb`, `@elastic/elasticsearch` | Все работают без нативных зависимостей. |

## 3. Общая схема

```
┌───────────────────────────── Extension Host (Node.js) ─────────────────────────────┐
│                                                                                    │
│  vscode/  (адаптеры к API редактора)                                               │
│   ├─ tree/       дерево подключений и объектов                                     │
│   ├─ editor/     команды Run, CodeLens, автодополнение, статус-бар, диагностика    │
│   └─ panels/     хосты webview-панелей (результаты, форма подключения, …)          │
│          │                                                                         │
│          ▼                                                                         │
│  services/  (логика приложения, без UI)                                            │
│   ConnectionStore · ConnectionManager · QueryRunner · ResultStore · MetadataCache  │
│          │                                                                         │
│          ▼                                                                         │
│  drivers/  (по одному на СУБД, общий интерфейс Driver + Dialect)                   │
│   mysql · postgres · sqlite · …        ── грузятся лениво ──►  сетевые соединения  │
│          │                                                                         │
│          ▼                                                                         │
│  core/   (чистая логика: SQL-токенизатор, модели, значения, ошибки)                │
│                                                                                    │
└──────────────────────────────▲─────────────────────────────────────────────────────┘
                               │ postMessage (типизированный RPC, src/shared/protocol)
┌──────────────────────────────▼──────────── Webview (браузер, Svelte) ──────────────┐
│  apps/: result-grid · connection-form · table-designer · …                         │
│  components/: Grid, Button, Input, Select, Tabs, …                                 │
└────────────────────────────────────────────────────────────────────────────────────┘
```

### Правило зависимостей (проверяется ESLint)

```
vscode/  →  services/  →  drivers/  →  core/
   └──────────────┴────────────┴──────→  shared/
webview/ ─────────────────────────────→  shared/
```

- `core/` и `shared/` не импортируют `vscode`, Node-модули ввода-вывода и вообще ничего из других слоёв.
- `drivers/` и `services/` **не импортируют `vscode`**. Всё, что им нужно от редактора (хранилище, секреты, логгер), они получают через маленькие интерфейсы в конструкторе.
- Только `vscode/` и `extension.ts` знают про API редактора.
- `webview/` общается с host только через протокол из `shared/`.

Благодаря этому почти вся логика тестируется без запуска VS Code.

## 5. Ключевые абстракции

Эскизы — точные сигнатуры уточняются при реализации.

### Driver, Session, Dialect

```ts
/** Описание СУБД. Создаёт сессии, сам соединений не держит. */
export interface Driver {
  readonly id: DriverId;                    // 'mysql' | 'postgres' | 'sqlite' | …
  readonly dialect: Dialect;
  readonly capabilities: DriverCapabilities; // schemas, cancel, transactions, …
  openSession(config: ResolvedConnectionConfig): Promise<Session>;
}

/** Одно живое соединение. У каждого SQL-редактора — своя сессия. */
export interface Session extends AsyncDisposable {
  execute(sql: string, options: ExecuteOptions): AsyncIterable<ExecuteEvent>;
  cancel(): Promise<void>;
  metadata: MetadataReader;
}

/** Всё, что отличает SQL разных СУБД. UI генерирует SQL только через Dialect. */
export interface Dialect {
  quoteIdentifier(name: string): string;
  literal(value: CellValue): string;
  paginate(sql: string, limit: number, offset: number): string;
  keywords: readonly string[];
  // генерация DDL/DML — по мере роста функциональности
}
```

`execute` возвращает поток событий (`columns`, `rows` батчами, `done`, `message`), а не массив целиком. Так один и тот же код подходит и для 10 строк, и для миллиона: можно показать первые строки сразу и остановиться на лимите.

### Значения ячеек

Всё, что приходит из драйверов, нормализуется в `CellValue` (`src/shared/cell-value.ts`), например:

```ts
type CellValue =
  | null
  | string
  | number
  | boolean
  | { kind: 'bigint' | 'decimal'; text: string }     // без потери точности
  | { kind: 'datetime'; text: string }               // как вернула БД, без сдвига часовых поясов
  | { kind: 'binary'; size: number; preview: string } // hex-превью, полные данные — по запросу
  | { kind: 'json'; text: string };
```

### Результаты: данные живут в host

```
QueryRunner ──rows──► ResultStore (host, в памяти, с лимитом)
                           ▲
webview: «нужны строки 1200–1300»  ──RPC──┘   ◄── ответ окном строк
```

Webview хранит только видимые строки (плюс небольшой запас). Поэтому таблица остаётся быстрой на любом объёме, а сортировка/экспорт выполняются в host.

### RPC host ↔ webview

- Конверт сообщений и `RpcPeer` — в `src/shared/rpc.ts`, один и тот же класс работает и в host, и в webview.
- Три вида: `request` (с `id`, ждёт `response`), `response`, `event` (без ответа). Запросы и события ходят в обе стороны.
- Протокол каждой панели — в `src/shared/protocols/<panel>.ts` через `defineProtocol({ host, webview })`: что обрабатывает каждая сторона. Описание — схемами из `src/shared/schema.ts`, TypeScript-типы выводятся из них (D22).
- Каждое входящее сообщение проверяется на форму перед обработкой — webview недоверенная сторона: неизвестные поля, лишние ключи, `__proto__`, слишком длинные строки отбрасываются; ответ с ошибкой несёт только `code` и `message`, без стека.
- У запроса есть таймаут (30 с по умолчанию); `dispose()` отклоняет все ожидающие запросы.
- **Жизненный цикл webview (D21):** скрытая вкладка выгружается и при показе загружается заново. Поэтому страница при каждой загрузке шлёт событие `ready`, а host в ответ заново отправляет ей состояние. Источник правды всегда host (это и так следует из D6).

## 6. Основные потоки

**Выполнение запроса**
1. `Ctrl+Enter` → `vscode/editor` определяет текст (выделение или запрос под курсором через `core/sql`).
2. `QueryRunner` берёт сессию документа у `ConnectionManager` (создаёт её при необходимости).
3. Safe mode проверяет опасные запросы (V2) → `session.execute()`.
4. События пишутся в `ResultStore`; панель результатов получает `event: resultUpdated` и запрашивает видимые строки.
5. Ошибка → сообщение в панели + Diagnostics в редакторе (V3).

**Редактирование данных (V2)**
1. Webview копит изменения локально и показывает их подсветкой.
2. «Сохранить» → host получает список изменений → `Dialect` строит `UPDATE/INSERT/DELETE` с условием по ключу.
3. Предпросмотр SQL → выполнение в одной транзакции → при ошибке откат и показ, какая строка не прошла.

## 7. Производительность — правила

- `activationEvents` только конкретные: открытие нашего view, наши команды. Никакого `*`.
- Драйвер собирается отдельным бандлом (`dist/drivers/<id>.js`) и загружается `require` только при первом подключении к этой СУБД.
- Ничего синхронно тяжёлого в extension host: SQLite и парсинг больших файлов — в `worker_threads`.
- Лимит строк по умолчанию для запросов из редактора (например, 1000), с подгрузкой при прокрутке.
- Виртуализация в таблице: в DOM только видимые строки и колонки.
- Метаданные кэшируются, автодополнение не ходит в БД на каждое нажатие клавиши.
- `.vscodeignore` держит `.vsix` маленьким: только `dist/`, `resources/`, лицензии.

## 8. Безопасность — правила

- Пароли, passphrase ключей и токены — только в `context.secrets`. В globalState и файлы — никогда.
- Webview: строгий CSP с nonce, `localResourceRoots` только на `dist/webview`, никаких внешних ресурсов и `eval`.
- Пользовательские значения в SQL — через параметры драйвера; идентификаторы — через `dialect.quoteIdentifier`.
- Логи не содержат паролей и строк подключения с паролями.
- Опасные операции всегда показывают SQL перед выполнением.

## 9. Ошибки и логирование

- Один класс `DbError` с полями `code`, `message`, `detail?`, `position?` (позиция ошибки в SQL). Драйвер переводит свои ошибки в него.
- Пользователь видит короткое понятное сообщение; подробности — в Output Channel.
- Любой `catch` либо обрабатывает ошибку, либо логирует и пробрасывает дальше. Пустых `catch {}` нет.
- Уровни логов: `error`, `warn`, `info`, `debug` (уровень меняется в настройке `datanest.logLevel`, сразу, без перезапуска).
- Логгер сам маскирует пароли и токены (`core/logging/redact.ts`): в URL подключений, парах `password=…`/JSON и в SQL `IDENTIFIED BY '…'`/`PASSWORD '…'`. Это страховка — передавать секреты в лог всё равно нельзя.
- Сервисы и драйверы получают интерфейс `Logger` (и `logger.child('mysql')` для своей области), а не Output Channel.
- Каждая команда регистрируется через `guardCommand`: ошибка уходит в лог с подробностями, пользователь видит короткое сообщение, отмена (`DbError` с кодом `cancelled`) — молча.

## 10. Стиль кода

### TypeScript
- `strict: true`, `noUncheckedIndexedAccess: true`, `noImplicitOverride: true`.
- Никакого `any`. Где тип неизвестен — `unknown` и проверка. Non-null `!` — только с комментарием, почему это безопасно.
- Только именованные экспорты, без `export default`.
- `async/await`, без `.then()`-цепочек. Floating promises запрещены линтером.
- Классы — для сервисов с состоянием; чистые функции — для всего остального.
- Зависимости передаются через конструктор. Глобальных синглтонов нет; всё собирается в `extension.ts`.
- Всё, что подписывается на события или держит ресурсы, реализует `Disposable` и попадает в `context.subscriptions`.

### Именование
- Файлы и папки: `kebab-case.ts`. Svelte-компоненты: `PascalCase.svelte`.
- Типы и классы: `PascalCase`. Функции и переменные: `camelCase`. Константы модуля: `UPPER_SNAKE_CASE`.
- Id команд и настроек: `<extId>.<area>.<action>`, например `<extId>.query.run`.

### Организация
- Один модуль — одна ответственность. Ориентир — до ~300 строк на файл; больше — повод разделить.
- Комментарии объясняют **почему**, а не что. JSDoc — для публичных интерфейсов (`Driver`, сервисы).
- Тексты интерфейса — через `vscode.l10n.t()` (host) и общий словарь (webview) с первого дня, чтобы перевод не требовал правок кода.
- Никаких магических строк для SQL в UI — только через `Dialect`.

### Форматирование (Prettier)
2 пробела, одинарные кавычки, точки с запятой, ширина строки 100, trailing commas.

### Git
- Коммиты по [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`.
  В сообщении удобно ссылаться на шаг: `feat(grid): column resize (V1.19)`.
- Ветка `main` всегда собирается и проходит тесты.
- Каждый готовый шаг помечаем аннотированным git-тегом с именем шага: `git tag -a V0.8 -m ""`. Если один коммит закрывает несколько шагов — ставим на него все теги. Коммит и теги сразу пушим: `git push origin main <теги>`.
- Версии — SemVer, соответствие версий и вех — в ROADMAP. Каждый релиз описан в `CHANGELOG.md`.

|---|---|---|

| `npm run test:coverage` | Unit-тесты с отчётом о покрытии (`coverage/`) |
| `npm run test:e2e` | Сборка + smoke-тесты в настоящем VS Code минимальной версии (`test/e2e/`, mocha) |

| `npm run test:integration` | Интеграционные тесты (`test/integration/`) против БД из Docker; без `db:up` сразу падают с подсказкой |
| `npm run lint` / `npm run typecheck` | ESLint + Prettier / `tsc` для host, e2e и `svelte-check` для webview |

### CI

`.github/workflows/ci.yml` запускается на каждый push в `main`, на теги шагов и на pull request:
lint + типы + `npm audit` → unit-тесты и e2e на **Linux, Windows и macOS** → интеграционные тесты на БД из `docker/compose.yml` → сборка `.vsix` (артефакт). Шаг отмечается `[x]` и получает тег только при зелёном CI.

### Правила тестов (обязательны всегда)

1. **Тесты пишутся вместе с фичей, в том же шаге.** Шаг без тестов не считается готовым (`[x]` не ставим).
   Тестируем по полной: обычный сценарий, граничные случаи, ошибки и некорректный ввод.
2. **Все тесты лежат только в папке `test/` в корне проекта.** Никаких `*.test.ts` / `*.spec.ts` рядом с кодом
   в `src/` или `webview/`. Это проверяет отдельный тест `test/unit/repo/test-layout.test.ts`, и Vitest ищет тесты только в `test/`.
3. **Структура `test/`:**
   ```
   test/
   ├─ unit/          # зеркалит src/: src/core/sql/split.ts → test/unit/core/sql/split.test.ts
   │  ├─ webview/    # зеркалит webview/src/
   │  └─ repo/       # проверки самого репозитория: манифест, раскладка файлов, конфиги
   ├─ integration/   # драйверы против реальных БД из Docker (*.int.test.ts)
   ├─ e2e/           # smoke-тесты в настоящем VS Code
   ├─ helpers/       # фейки и утилиты для тестов (FakeMemento, FakeSecretStorage, …)
   └─ fixtures/      # тестовые данные: SQL-файлы, CSV, дампы
   ```
4. **Имена:** файл теста = имя модуля + `.test.ts`. `describe` — модуль или функция, `it` — поведение
   простыми словами: `it('splits statements on semicolons outside strings')`.
5. **Тесты независимы и детерминированы:** не зависят от порядка запуска, не ходят в интернет,
   не используют реальные задержки (`vi.useFakeTimers()`), убирают за собой временные файлы.
6. **Без `vscode` в unit-тестах.** Логику тестируем через интерфейсы и фейки из `test/helpers/`;
   код, который требует `vscode`, проверяем в `test/e2e/`.
7. **Найденный баг сначала воспроизводим тестом**, потом чиним — тест остаётся навсегда.
8. Перед отметкой шага `[x]` должны проходить `npm run lint`, `npm run typecheck` и `npm test`.
