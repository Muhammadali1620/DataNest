# Roadmap

Бесплатный открытый клиент баз данных для VS Code и его форков (VSCodium, Cursor, Windsurf и др.).
Цель — удобство уровня лучших платных расширений, но без платных функций, аккаунтов и ограничений.

> Рабочее название пока не выбрано (шаг V0.0). Технические решения описаны в [ARCHITECTURE.md](ARCHITECTURE.md).

---

## Принципы проекта

1. **Бесплатно навсегда.** Никаких premium-функций, лимитов на число подключений, регистрации и телеметрии.
2. **Свой код с нуля.** Мы повторяем *идеи и удобство* популярных клиентов, но не код, тексты, иконки и бренд.
   Исходники чужих расширений не открываем и не копируем — ориентируемся только на пользовательский опыт.
3. **Стабильность важнее количества фич.** Версия выходит, только когда всё в ней работает без глюков.
4. **Скорость.** Расширение не тормозит редактор: ленивая загрузка, виртуализация таблиц, тяжёлое — вне UI-потока.
5. **Работает везде.** Без нативных модулей — одинаково в VS Code и форках, на Linux, Windows и macOS.
6. **Фичи, требующие наших серверов, не делаем** (облачная синхронизация, аккаунты и т.п.).

## Как работать с этим файлом

- Статусы шагов: `[ ]` не начато · `[~]` в работе · `[x]` готово · `[-]` отменено/перенесено (с пометкой куда).
- Шаг = небольшой законченный кусок работы (обычно один коммит или PR), который можно проверить.
- ⭐ — фича, которой нет в оригинале или которая сделана заметно лучше.
- Файл живой: если что-то меняется — правим план здесь, а важные технические решения записываем в журнал решений в `ARCHITECTURE.md`.

**Шаг готов, когда:** код собран без ошибок и предупреждений линтера, **написаны и проходят тесты на всё, что добавлено в шаге** (обычный сценарий, граничные случаи, ошибки), проверено руками в Extension Development Host.

**Тесты — всегда и только в `test/`.** Пишем их в том же шаге, что и фичу, а не «потом». Раскладка и правила — в [ARCHITECTURE.md, раздел 11](ARCHITECTURE.md#11-тестирование).

**Версия готова, когда:** все шаги `[x]` или осознанно перенесены, пройден ручной тест-план, обновлены `CHANGELOG.md` и `README.md`.

## V1 — Первое рабочее (0.1.0)

**Итог:** можно подключиться к MySQL/MariaDB, PostgreSQL или SQLite, ходить по дереву, открывать таблицы, писать и выполнять SQL, смотреть результаты в быстрой таблице и экспортировать их. Первая публикация.

> **Статус (2026-10-24):** опубликовано в Open VSX — https://open-vsx.org/extension/datanest/datanest (текущая версия 0.1.2).
> Все шаги V1.1–V1.28 закрыты. За владельцем осталось: ручной прогон тест-плана в VS Code, VSCodium и Cursor (V1.27), съёмка скриншотов для README (V1.26) и загрузка `.vsix` в VS Marketplace (V1.28).

### Подключения
- [x] **V1.1** Модель `ConnectionConfig`, хранилище подключений (globalState), пароли — только в SecretStorage.
  `core/model/connection.ts` (типы, валидация, порты по умолчанию), `services/connection-store.ts` (CRUD, дубликат с копией пароля, события, защита от битого состояния).
- [x] **V1.2** Интерфейс `Driver` + `Dialect`, реестр драйверов, ленивая загрузка бандла драйвера.
  `drivers/driver.ts` (Driver/Session/Dialect/MetadataReader, поток `ExecuteEvent`), `drivers/registry.ts` (ленивый `require` бандла, кэш, повтор после ошибки), `shared/cell-value.ts`, `core/model/objects.ts`.
- [x] **V1.3** Драйвер MySQL/MariaDB (`mysql2`): подключение, запросы, метаданные, отмена запроса.
  Поток событий через `core/async-queue.ts`, лимит строк с безопасным `KILL QUERY` (без гонки со следующим запросом), типы без потери точности, маппинг ошибок. Интеграционные тесты идут на MySQL 8 и MariaDB.
- [x] **V1.4** Драйвер PostgreSQL (`pg`): то же + схемы.

- [x] **V1.5** Драйвер SQLite (`node:sqlite` в `worker_threads`, D5), открытие файла, создание новой БД. E2E на трёх ОС подтверждает выводы V0.12 для Windows и macOS.
  Worker собирается в `dist/drivers/sqlite-worker.js`, протокол host↔worker пригоден для structured clone. Отмена — брошенный worker (D25): `terminate()` не прерывает синхронный вызов SQLite. E2E грузит драйвер из готового бандла, как это делает `DriverRegistry`.
- [x] **V1.6** `ConnectionManager`: открытие/закрытие, отдельная сессия для каждого редактора, автопереподключение при обрыве, статусы.
  Сессии по владельцу (`editor:<uri>`, `tree:<id>`), `ManagedSession` замечает обрыв связи и роняет мёртвую сессию — переподключение происходит перед следующим запросом, упавший запрос никогда не повторяется сам (D26). Есть `test()` для кнопки «Проверить подключение».
- [x] **V1.7** Форма подключения (webview): тип БД, хост/порт/пользователь/пароль/БД, выбор файла для SQLite, «Проверить подключение», редактирование, дублирование, удаление.

### SQL-редактор
- [x] **V1.12** «Новый запрос»: SQL-документ, привязанный к подключению и базе; в статус-баре видно и можно переключить активное подключение/БД.
  `editor/document-bindings.ts` (привязка документ → подключение/база) и `editor/status-text.ts` (текст статус-бара) — без `vscode`, под тестами. Из дерева запрос открывается сразу на нужной базе; закрытие документа освобождает его сессию.
- [x] **V1.13** SQL-токенизатор и разбиение на запросы: строки, комментарии, `$$` в PG, бэктики, `DELIMITER` в MySQL. Покрыть unit-тестами.
  `core/sql/tokenizer.ts` (синтаксис задаётся по драйверу: экранирование `\`, `#`-комментарии, вложенные блочные, dollar-quoting) и `core/sql/split.ts` (`splitStatements`, `statementAt`, `statementsIn` со смещениями). Проверено в том числе на настоящих seed-скриптах: тела процедур с `DELIMITER //` и `$$` не разрезаются.
- [x] **V1.14** Выполнение: `Ctrl+Enter` — запрос под курсором или выделение, `Ctrl+Shift+Enter` — весь файл, CodeLens «▶ Run» над каждым запросом.
  `services/query-runner.ts` (один прогон на документ, остановка на первой ошибке, лимит строк, сброс кэша метаданных после DDL) и `services/result-store.ts` (результаты живут в host, окна строк — для V1.17). Ошибка запроса — это результат, а не падение. Пока итог виден короткой строкой в статус-баре; таблица будет в V1.19. Новый код ошибки `busy` — «в этом редакторе уже идёт запрос». Настройка `datanest.rowLimit`.
- [x] **V1.15** Отмена выполняющегося запроса (кнопка и команда), таймер выполнения в статус-баре.
  `QueryRunner` сообщает о начале и конце прогона, `editor/run-status.ts` показывает счётчик времени (обновление раз в 200 мс) и отменяет запрос по клику; кнопка «Отменить» в заголовке редактора появляется по контекст-ключу `datanest.queryRunning`.
- [x] **V1.16** Автодополнение (база): ключевые слова диалекта, базы/схемы, таблицы, колонки после `table.` и в контексте `FROM`/`JOIN`.
  `core/sql/completion-context.ts` определяет по токенам, что ожидается (таблица, колонка, после точки), и собирает таблицы запроса с алиасами; внутри строк и комментариев подсказок нет. Ключевые слова переехали в `core/sql/keywords.ts` — один список для диалектов и редактора. Данные берутся только из кэша метаданных.

### Результаты
- [x] **V1.17** Хранилище результатов на стороне host + протокол подгрузки окнами строк (webview запрашивает видимый диапазон).
  Протокол `shared/protocols/result-grid.ts`: страница просит строки окнами (до 2000 за раз), сами строки остаются в host. Панель результатов — одна на документ, рядом с запросом, с вкладками по запросам и кнопкой отмены; команда «Показать результаты» открывает её заново. В схемы добавлено объединение типов (`union`) и валидация значений ячеек.
- [x] **V1.18** Единая сериализация значений: NULL, bigint, decimal, даты/время, binary, JSON — без потери точности.
  `shared/cell-text.ts` — один источник текста значения (`cellText`) и JSON-формы (`cellJson`) для таблицы, копирования и экспорта; точные типы остаются текстом, чтобы JSON-число их не округлило. Интеграционный тест `value-fidelity` проверяет одно и то же на MySQL, MariaDB, PostgreSQL и SQLite. Бинарные данные в ячейке показываются размером, а в буфер и экспорт уходят как hex — это осознанное различие.
- [x] **V1.19** Таблица результатов: виртуализация строк и колонок, закреплённый заголовок, ресайз колонок, номера строк, явный NULL, цвета из темы VS Code.
  Геометрия (`virtual.ts`) и ширины колонок (`columns.ts`) — чистые функции под тестами; в DOM только видимое окно (100 000 строк → меньше 100 элементов), заголовок и номера строк закреплены, ширина тянется за указателем и не уходит ниже минимума, двойной клик по разделителю подгоняет по заголовку. Пока браузер не сообщил размер области, считается один экран — первые строки грузятся сразу.
- [x] **V1.20** Выделение ячеек/диапазонов мышью и клавиатурой, копирование в TSV (вставляется в Excel/Sheets).
  `selection.ts` — модель выделения (мышь с протягиванием, Shift-клик, стрелки, Shift+стрелки, Ctrl+Home/End, PageUp/Down, Ctrl+A) под тестами; `shared/tsv.ts` закавычивает значения с табами и переводами строк, поэтому вставка в Excel не разъезжается. Копирование идёт через host (`vscode.env.clipboard`), строки под выделением докачиваются. Попутно исправлено: панель результатов больше не забирает фокус у редактора.
- [x] **V1.21** Сортировка по клику на заголовок и быстрый поиск по результату.
  Сортировка и поиск идут в host по **всем** строкам, а не только по загруженным: `shared/cell-compare.ts` (точные числа сравниваются по тексту, NULL всегда в конце, сортировка устойчивая) и `shared/cell-search.ts`. В панели: «Сохранить N изменений» (Ctrl+S), «Предпросмотр SQL» (открывает транзакцию в новом SQL-документе), «Отменить все» (с подтверждением), «Откатить строки» для выделения. Текст — целиком, с числом символов и строк, перенос строк включается; JSON (колонка JSON или текст, который разбирается как объект/массив) форматируется и подсвечивается, переключатель «Формат / Как есть». Форматирование идёт по токенам, а не через `JSON.parse`/`stringify`, поэтому числа вроде `12345678901234567890` и `0.10` не теряют вид (`webview/.../json-view.ts`); битый JSON показывается как есть с пометкой. Binary: hex-дамп страницами по 4 КБ и картинка из BLOB (PNG, JPEG, GIF, WebP, BMP по первым байтам, не по типу колонки; SVG намеренно нет — это текст со скриптами), рисуется через `data:`-URL, CSP не менялся. Полные байты не едут в ячейке: драйверы кладут их в `WeakMap` рядом с ячейкой (`shared/binary-bytes.ts`, до 16 МБ), панель берёт их запросом `binaryBytes`; у SQLite воркер пересылает байты вместе со строками (`drivers/sqlite/blobs.ts`). Значение больше лимита — предупреждение и hex первых 256 байт. Панель только читает: правка длинного текста остаётся ячейкой (V2.2).
- [x] **V2.6** Фильтр на сервере: конструктор условий по колонкам + ручной `WHERE`; сортировка на сервере по заголовку.
  В табличном виде кнопка «Фильтр» открывает панель: строки «колонка · условие · значение» (равно, не равно, меньше/больше и не меньше/не больше, содержит, не содержит, начинается, заканчивается, NULL, не NULL) и поле своего `WHERE`; всё соединяется через AND. Правила — в `shared/table-filter.ts` (их проверяют и страница, и host), SQL строит `services/table-filter-sql.ts` только через `Dialect`: имена — `quoteIdentifier`, значения — `literal`, подстановки `%`/`_` в «содержит» экранируются (`ESCAPE '!'`), для чисел и дат колонка приводится к тексту, в PostgreSQL поиск через `ILIKE` (новый метод `Dialect.likeText`). Свой `WHERE` проверяется токенайзером (одно условие, без `;` и незакрытых кавычек) и кладётся в скобки на отдельных строках, чтобы `--` в нём не съел закрывающую. Клик по заголовку в табличном виде теперь сортирует всю таблицу на сервере (`ORDER BY`, с первой страницы); в результатах запросов остаётся сортировка в host. Счётчик строк учитывает фильтр. `TableViewer` хранит состояние вида (фильтр, порядок) и перечитывает его через `reload`; результат с ошибкой остаётся табличным видом, поэтому неудачный фильтр можно исправить, не закрывая панель. Сквозной тест на MySQL, MariaDB, PostgreSQL и SQLite: сравнения, регистр, шаблонные символы, кавычки и `\` в значениях, NULL, свой `WHERE`, сортировка со страницами.
- [x] **V2.7** Пагинация: размер страницы, переход на страницу, «загрузить всё» с предупреждением, точный или быстрый приблизительный count.
  Внизу табличного вида: «Назад / Вперёд», диапазон строк, поле «Страница N из M» (Enter — перейти; номер за пределами сжимается до последней страницы), выбор «Строк на странице» (50…5000 и текущее значение), «Загрузить всё». Арифметика — в `webview/.../pager-model.ts`. Размер страницы живёт в состоянии вида (`TableViewer`) и переживает листание, фильтр и сортировку; смена размера начинает с первой страницы. «Загрузить всё» ставит размер страницы по числу строк (потолок — 1 000 000) и спрашивает подтверждение (модально) выше 50 000 строк либо когда число неизвестно или приблизительно. Количество строк: таблицы до 100 000 строк считаются точно `COUNT(*)`, у больших без фильтра сначала показывается оценка сервера — MySQL/MariaDB `information_schema.TABLES.TABLE_ROWS`, PostgreSQL `pg_class.reltuples` (новый необязательный `Dialect.estimateRowsSql`; у SQLite статистики нет, он всегда считает) — с пометкой «примерно» и кнопкой «Посчитать», которая делает точный подсчёт. Оценка не годится как граница: «Вперёд» работает по заполненности страницы, число страниц не показывается. При фильтре считаем только точно. Сохранение правок перечитывает строки с текущим размером страницы, а не с настройкой. Сквозной тест на 150 000 строк в MySQL, MariaDB, PostgreSQL и SQLite: оценка, точный подсчёт, страницы 5000/40 000, короткая последняя страница, страница за концом. Интеграционные файлы теперь идут последовательно: сид-тест перечисляет таблицы общей БД, и параллельные тесты с созданием таблиц ему мешали.
- [x] **V2.8** «Копировать как»: INSERT, UPDATE, JSON, CSV, Markdown, список для `IN (...)` ⭐.
  Меню «Копировать как…» в строке вкладок копирует выделенный прямоугольник (или весь результат, если выделения нет): текст с заголовками (TSV), CSV, JSON, таблица Markdown, SQL INSERT, SQL UPDATE, список `IN (…)`. Рендер — в `services/copy-as.ts` (чистая функция), чтение ячеек и ограничения — в `services/result-copier.ts`, буфер обмена пишет панель. Копируется то, что видно в таблице, в том числе несохранённые правки. SQL строится только через `Dialect`: INSERT — по одному оператору на строку, имена колонок берутся из таблицы (вычисляемые колонки пропускаются), у результата не из одной таблицы вместо имени подставляется `table_name`; UPDATE ставит выбранные не ключевые колонки и находит строку по ключу, даже если ключ не выделен (только для редактируемых результатов); `IN` берёт первую выделенную колонку, без NULL (они в `IN` не совпадают) и без повторов. JSON хранит точные числа текстом, дубли имён колонок нумеруются, Markdown выравнивает числа вправо и экранирует `|` и переводы строк. За раз не больше 100 000 строк. Сквозной тест на MySQL, MariaDB, PostgreSQL и SQLite: значения с `'`, `\`, переводом строки, `;`, юникодом, NULL после INSERT/UPDATE читаются точно такими же.
- [x] **V2.9** Экспорт результата: SQL INSERT, Markdown, XLSX.

XLSX пишется без зависимостей: `services/zip.ts` (ZIP с deflate, CRC32, имена в UTF-8) и `services/xlsx.ts` (книга из одного листа, строки внутри ячеек, жирная закреплённая шапка, ширина колонок по содержимому). Лимиты формата — 1 048 575 строк, 16 384 колонки, 32 767 символов в ячейке — проверяются, а слишком большой результат даёт понятное сообщение. - [x] **V2.10** История запросов: сохранение, поиск, повторный запуск, фильтр по подключению.
  Команда «История запросов» (значок в заголовке SQL-редактора) открывает быстрый выбор: поиск по всему тексту запроса (слова в любом порядке, без учёта регистра), у каждой строки кнопки «Запустить снова», «Копировать SQL», «Удалить»; Enter открывает запрос в новом редакторе на том же подключении и базе, кнопки сверху — «Фильтр по подключению» и «Очистить» (все записи или только выбранного подключения, с подтверждением). Строка показывает запрос, подключение, время, длительность, число строк или текст ошибки. Запись делает `QueryRunner` после каждого запроса (успешного, с ошибкой, по таймауту); сбой истории не может уронить запрос. `services/history.ts`: хранится в `globalState`, лимит — настройка `datanest.historyLimit` (по умолчанию 500, `0` выключает и стирает), подряд идущие одинаковые запросы на одном подключении сворачиваются в одну запись со счётчиком «×N», запросы длиннее 100 000 символов не пишутся. Пароли маскируются тем же `redactSecrets`, что и логи (`IDENTIFIED BY '…'`, `password = …`): такая запись помечена, открывается, но «Запустить снова» её не выполняет. Повреждённая история не мешает запуску. Подключение, которого больше нет, показывается по прежнему имени.
- [x] **V2.11** Safe mode: подтверждение `DELETE`/`UPDATE` без `WHERE`, `DROP`, `TRUNCATE`.
  Перед любым запуском (Ctrl+Enter, «Выполнить всё», линза над запросом, «Запустить снова» из истории) запросы проверяются: `core/sql/danger.ts` читает токены, а не текст, поэтому `WHERE` в строке, комментарии, имени (`somewhere`) или подзапросе за условие не считается, а `ON CONFLICT … DO UPDATE` и `ON DUPLICATE KEY UPDATE` без `WHERE` не тревожат. Распознаются `DELETE`/`UPDATE` без собственного `WHERE` (в том числе после `WITH …` и в `EXPLAIN ANALYZE`, который запрос выполняет, — простой `EXPLAIN` не трогается), любой `DROP` и `TRUNCATE`. Настройка `datanest.safeMode`: `confirm` (по умолчанию) — модальное окно со списком опасных запросов и кнопкой «Всё равно выполнить», `block` — не выполнять, `off` — без вопросов. Один вопрос на весь запуск, а не по запросу. Правки в сетке и табличный вид не затрагиваются: их SQL строит DataNest сам и всегда по ключу. Не закрыто: `ALTER TABLE … DROP COLUMN`, `DROP` внутри процедуры и изменяющие запросы внутри `WITH` в скобках (PostgreSQL) — проверяется только верхний уровень.
- [x] **V2.12** Карточка записи: вертикальный просмотр и редактирование одной строки ⭐.
  Кнопка «Запись» (или Shift+F4) открывает справа форму строки в фокусе: каждая колонка — имя, тип, поле. Поля те же, что в ячейке (число, текст, дата, список для bool и enum), но для текста и JSON — растущее многострочное поле (Enter — отправить, Shift+Enter — новая строка). Вычисляемые, бинарные и все колонки нередактируемого результата показываются текстом; удалённая строка — только для чтения с пометкой, новая — с пометкой «новая». Стрелки ↑/↓ в шапке листают строки, сохраняя выбранную колонку (Grid получил `revealColumn`). Карточка и панель значения занимают одно место, открыта может быть только одна.
- [x] **V2.13** Переход по внешнему ключу из ячейки к связанной записи ⭐.
  Новый метод `MetadataReader.listForeignKeys` во всех трёх драйверах (MySQL/MariaDB — `KEY_COLUMN_USAGE`, PostgreSQL — `pg_constraint` с разбором `conkey`/`confkey`, SQLite — `pragma_foreign_key_list`; ключ без явных целевых колонок указывает на первичный ключ целевой таблицы), с кэшем метаданных. Внешние ключи читаются вместе с проверкой редактируемости, поэтому ссылки есть у результатов «из одной таблицы с ключом» (в том числе табличный вид); неудача чтения не отнимает редактирование. В сетке ячейки колонок внешнего ключа со значением помечены ↗, подсказка «Ctrl+клик или F12: открыть строку в таблице»; в карточке записи у такого поля есть кнопка «↗ таблица». Составные ключи работают, если все их колонки есть в результате. Переход (`services/result-links.ts`) берёт значения так, как их показывает таблица (с несохранёнными правками), и открывает целевую таблицу в её собственной панели с фильтром по ключу из V2.6, то есть связанная строка видна в обычном табличном виде, а фильтр можно сменить. NULL-ключ и бинарный ключ не открываются, пользователь видит причину. Сквозной тест на MySQL, MariaDB, PostgreSQL и SQLite: числовой и текстовый ключ, NULL, метаданные; интеграционные тесты метаданных, включая ключи между схемами PostgreSQL и составные/неявные ключи SQLite. Обратный переход («кто ссылается на эту строку») в план V2 не входил.
- [x] **V2.14** Скрытие и закрепление колонок, автоширина по содержимому.
  Кнопка «Колонки» открывает список: флажок у каждой колонки скрывает её, 📌 закрепляет, «Показать все», «По содержимому», «Сбросить». Сетка работает в позициях на экране, а наружу отдаёт номера колонок результата (`SelectionInfo`): стрелки и выделение идут по тому, что нарисовано, а копирование (`Ctrl+C`, «Копировать как…») берёт ровно видимые колонки в порядке на экране — для этого запрос `copyAs` теперь принимает список колонок вместо `left/right`. - [x] **V3.5** Конструктор таблицы: индексы и внешние ключи.
  В конструкторе появились вкладки «Индексы» и «Внешние ключи». Индекс — имя (по умолчанию `ix_<таблица>_N`), упорядоченный список колонок (метки-«чипы» с ✕ и список для добавления, порядок = порядок в ключе), «уникальный». Драйвер просто подключается к этому порту, поэтому отмена запроса (отдельное соединение) тоже идёт через туннель, а TLS в V4.3 проверит сертификат по настоящему имени (`tlsServerName`). `TunnelPool` держит один туннель на подключение: открывается с первой сессией, закрывается с последней, упавший туннель забывается — следующая сессия откроет новый (D26). Если сервер БД недоступен с SSH-сервера, ошибка говорит это прямо («SSH-сервер … не может достучаться до db:5432»), а не «соединение сброшено». Ключ SSH-сервера проверяется как в OpenSSH: при первом подключении — окно с отпечатком `SHA256:…` и «Доверять», при смене ключа — громкое предупреждение и отказ, пока пользователь сам не доверится новому (`services/known-hosts.ts`, globalState). Нативные модули ssh2 и `cpu-features` при сборке заменяются заглушкой (D50). Тесты: unit — туннель против SSH-сервера `ssh2` внутри теста (пароль, keyboard-interactive, ключ с passphrase и без, чужой ключ, агент на локальном сокете, отказ и сбой проверки ключа хоста, цепочка из двух серверов, недоступная цель, молчащий сервер, обрыв, закрытие), пул, known hosts, менеджер, хранилище секретов, форма и страница; интеграционные — MySQL, MariaDB и PostgreSQL через настоящий OpenSSH из Docker (`datanest-ssh`, порт 7022) паролем, ключом и агентом, отмена запроса через туннель, неверный пароль, недоступная БД; e2e — `dist/ssh.js` открывает туннель внутри VS Code (там свой Node и BoringSSL).

- [x] **V4.3** SSL/TLS: CA, клиентский сертификат и ключ, режимы проверки.
  В форме — «SSL / TLS»: «Выключено», «Шифровать, сертификат не проверять» (`require`), «Шифровать и проверять издателя» (`verify-ca`), «…и имя хоста» (`verify-full`) — названия режимов как в `sslmode` PostgreSQL; файлы сертификата CA (пусто — доверенные CA системы), клиентского сертификата и ключа с кнопками «Обзор…» (сертификат без ключа и наоборот не сохраняются). В конфиге хранятся только пути, файлы читаются при каждом подключении (`drivers/common/files.ts`, `tls.ts`), так что обновлённый сертификат подхватывается сам. Служебное соединение отмены запроса идёт с теми же настройками TLS. Ошибки сертификата объясняются: «сертификат не выдан для "X"», «не доверен — выберите CA, который его выпустил», «срок действия» (mysql2 подменяет код ошибки, поэтому его ошибки распознаются по тексту). Тесты: unit — модель, хранилище, чтение файлов, параметры TLS обоих драйверов, проверка имени, разбор ошибок, форма и страница, репо-тест тестовых сертификатов (кем выпущены, для каких имён, срок, ключи совпадают, ключа CA в репозитории нет); интеграционные — MySQL и PostgreSQL из Docker с тестовым CA (`docker/tls`): без TLS соединение не шифруется, все три режима, чужой CA и системные CA отвергаются, `verify-full` по имени и по IP, клиентский сертификат (`REQUIRE X509` в MySQL, `cert` в `pg_hba` PostgreSQL), отмена запроса через TLS, через SSH-туннель имя проверяется по настоящему серверу и отвергается для имени, которого нет в сертификате.

- [x] **V4.6** Режим «Production»: цветной индикатор, подтверждение любых изменений, опциональный read-only ⭐.
  В форме — флажки «Рабочая (production) база» и «Только чтение» (независимы: read-only годится и для реплики). Production заметен везде: в дереве имя красное (если пользователь не выбрал другой цвет) с бейджем «P» и меткой «Production» в описании, у read-only — бейдж «RO» и метка; в строке состояния SQL-редактора — `$(warning) PROD` на красном фоне, у read-only — `$(lock)`. Что меняет базу, решает `core/sql/read-only.ts` по токенам, с осторожностью в сторону «меняет»: чтение — `SELECT` (без `INTO`, `FOR UPDATE/SHARE`, `LOCK IN SHARE MODE`), `WITH` без изменяющих CTE, `VALUES`, `TABLE`, `SHOW`, `DESCRIBE`, `EXPLAIN` (с `ANALYZE` — только если сам оператор читает), `USE`, транзакционные команды (кроме `READ WRITE`), безопасные `SET` (но не `GLOBAL`/`PERSIST`/`TRANSACTION`/`default_transaction_read_only`…), читающие `PRAGMA`; всё остальное — изменение. Политика (`services/write-policy.ts`) применяется в трёх местах: запуск из редактора (на production — одно модальное окно «Это изменит рабочую базу» со списком изменяющих операторов и пометками safe mode, второго вопроса safe mode нет, а его `block` по-прежнему запрещает; на read-only — отказ со списком), сохранение правок сетки (на production — «Сохранить N изменений в production?», на read-only — отказ, а результаты read-only подключения сразу «только чтение» с причиной `connection-read-only`), все изменения структуры через `schemaPerformer` — действия из дерева, конструктор таблиц, редактирование объектов (на production заголовок окна с SQL начинается с «PRODUCTION "имя":», на read-only — отказ до построения SQL). Read-only держит и сервер: PostgreSQL — `SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY`, MySQL/MariaDB — `SET SESSION TRANSACTION READ ONLY`, SQLite — файл открывается флагом `readOnly` (его нельзя снять из SQL, в отличие от `PRAGMA query_only`), так что скрытая запись — функция в `SELECT`, процедура — тоже не пройдёт. Тесты: unit — классификатор (70+ случаев: строки и комментарии, CTE с `DELETE`, `EXPLAIN ANALYZE`, `SET`, `PRAGMA`, диалект MySQL), политика, внешний вид в дереве и строке состояния, `schemaPerformer` (отказ, пометка, обычное подключение), редактируемость, менеджер, хранилище, форма и страница; интеграционные — на MySQL, MariaDB, PostgreSQL и SQLite read-only сессия читает, а `INSERT`/`UPDATE`/`DELETE` и `nextval()` в `SELECT` отвергает сам сервер, обычная сессия пишет; e2e — read-only SQLite в Node самого VS Code. Исправлено после шага: форма существующего подключения не получала флаги production и read-only, и сохранение снимало их — теперь в форму уходят все поля подключения, кроме id (тот же класс ошибки, что с TLS в V4.5), тест сверяет их со схемой.

- [x] **V4.8** Ручной режим транзакций: индикатор открытой транзакции, Commit/Rollback в статус-баре.
  Открыта ли транзакция, DataNest не угадывает по тексту запросов, а спрашивает сервер: у сессии новый необязательный метод `transactionState()` (`idle` / `open` / `failed`). PostgreSQL — статус из сообщения «готов к запросу» (`getTransactionStatus()` у `pg`; ошибка приходит раньше этого сообщения, поэтому ошибка внутри блока до его прихода считается сорвавшейся транзакцией — так PostgreSQL и делает), MySQL/MariaDB — флаг `SERVER_STATUS_IN_TRANS` в OK-пакете (его несут `BEGIN`, `COMMIT`, запись и DDL с неявной фиксацией; deadlock 1213 откатывает транзакцию целиком), SQLite — `isTransaction` воркера после каждого оператора (отмена бросает воркер — и транзакцию с ним). `ManagedSession` сообщает о смене состояния, `ConnectionManager` — подписчикам, а если сессия закрылась или потеряла связь с открытой транзакцией — говорит, что сервер её откатил. В строке состояния SQL-редактора рядом с подключением — режим («Автофиксация» / «Ручная фиксация», клик переключает режим этого редактора), при открытой транзакции — «Транзакция открыта» жёлтым и кнопки «Commit» и «Rollback», при сорвавшейся (PostgreSQL) — красным и только «Rollback»: `COMMIT` сорвавшейся транзакции PostgreSQL молча превращает в откат, поэтому DataNest его не предлагает. Индикатор работает и в автофиксации — если пользователь сам написал `BEGIN`. Ручной режим (`services/manual-commit.ts`): перед первым **изменяющим** оператором — `BEGIN`, чтение транзакцию не открывает (сессия не висит «idle in transaction» из-за `SELECT`); операторы управления транзакцией и DDL MySQL (который сам фиксирует) не оборачиваются. `core/sql/transaction-control.ts` по токенам отличает `BEGIN`/`START TRANSACTION`, `COMMIT`/`END`, `ROLLBACK`/`ABORT`, точки сохранения и `… PREPARED`, а также операторы, перед которыми MySQL/MariaDB неявно фиксируют транзакцию (DDL кроме временных таблиц, `GRANT`, `LOCK TABLES`, обслуживание, сам `BEGIN`) — при открытой транзакции запуск такого оператора сначала спрашивает «MySQL зафиксирует открытую транзакцию». Перед переключением подключения редактора — вопрос «Зафиксировать / Откатить», перед «Отключить» в дереве — «в N редакторах открыта транзакция»; закрытие редактора или обрыв связи — предупреждение, что сервер откатил транзакцию. Сохранение правок сетки в редакторе с открытой транзакцией теперь входит в неё через `SAVEPOINT` (`RELEASE` / `ROLLBACK TO SAVEPOINT`): раньше `BEGIN … COMMIT` сохранения в MySQL неявно фиксировал транзакцию пользователя, а в PostgreSQL фиксировал её своим `COMMIT`; в сорвавшуюся транзакцию сохранение не пускается, после сохранения — сообщение «изменения вошли в открытую транзакцию», предпросмотр SQL показывает точку сохранения. Новые команды «Зафиксировать транзакцию», «Откатить транзакцию», «Переключить автофиксацию / ручную фиксацию», настройка `datanest.transactionMode` (`auto` по умолчанию / `manual`) — с чего начинает новый редактор. Тесты: unit — разбор управления транзакцией и неявной фиксации MySQL, когда нужен `BEGIN`, режимы по документам, вид строки состояния, завершение транзакции (в том числе отказ фиксировать сорвавшуюся), события `ManagedSession` и менеджера (смена, закрытие, обрыв), ручной режим `QueryRunner` (один `BEGIN`, не для чтения и не для `COMMIT`, ошибка `BEGIN`), сохранение через точку сохранения, вопрос перед отключением; интеграционные — на MySQL, MariaDB, PostgreSQL и SQLite: состояние после `BEGIN`, записи, чтения, `COMMIT`, `ROLLBACK`, ошибки (PostgreSQL — `failed`), точки сохранения, DDL (MySQL фиксирует, остальные — нет), невидимость незафиксированного для другой сессии, отмена в SQLite; e2e — в настоящем VS Code ручной режим на SQLite: `CREATE` + `INSERT`, «Откатить» — таблицы нет, «Зафиксировать» — строка осталась.

Колонки таблицы — с типом и выбором «Заполняется из» (поле файла или «оставить базе»); по умолчанию поле с тем же именем без учёта регистра, пробелов и `_`, у CSV без заголовка — по порядку; вычисляемые колонки не заполняются. Предпросмотр первых 20 строк — значения уже в типах колонок, неподходящие помечены причиной («Введите дату как ГГГГ-ММ-ДД»), незаполняемые — `DEFAULT`. Режимы: «Всё или ничего» (одна транзакция, первая плохая строка откатывает всё) и «Пропускать неподходящие строки» (пачка, которую отверг сервер, повторяется по строке, чтобы потерять только плохие). Прогресс (прочитано, импортировано, с ошибкой, доля файла) и «Остановить»; итог со списком ошибок «Строка N, колонка X: причина» (первые 1000). На production — вопрос, read-only — отказ.
  Файл читается частями: `services/import/csv-parser.ts` (RFC 4180: кавычки, `""`, переводы строк в полях, CR/LF/CRLF, граница части в любом месте), `json-parser.ts` (массив объектов или JSON Lines; держит в памяти одну запись; числа сохраняют текст файла через `context.source`, вложенные объекты — JSON-текстом). Значения переводит `import-values.ts` по тем же правилам, что ввод в ячейку (`shared/cell-input.ts`): пустое поле и заданный текст (`\N`) — NULL, двоичные — `0x…`/`\x…`, `true/false` годятся для `TINYINT(1)` MySQL. `table-import.ts` вставляет пачками по 100 строк через `Dialect.dump.insert` (с `OVERRIDING SYSTEM VALUE` для identity в PostgreSQL) и после импорта двигает последовательности колонок с `serial`/identity. Интеграционные тесты: CSV и JSON в MySQL, MariaDB, PostgreSQL и SQLite — юникод, кавычки, многострочные поля, NULL, десятичные, булевы, откат в режиме «всё или ничего», нумерация продолжается после импортированных id.
- [x] **V5.4** Экспорт таблицы целиком потоком (не только загруженной страницы): CSV, JSON, SQL, XLSX.
  «Экспортировать данные…» на таблице и представлении в дереве: формат (CSV, JSON, SQL INSERT, Markdown, XLSX) → файл → строки идут с сервера прямо в файл с прогрессом («N строк») и отменой; итог — число строк, размер, время, «Показать в папке». «Выгрузить как…» в табличном виде теперь пишет всю таблицу с текущим фильтром и сортировкой, а не загруженную страницу (`TableViewer.fullQuery`); для результата запроса, обрезанного лимитом строк, — вопрос «Все строки» (запрос выполняется заново, только если он ничего не меняет) или «Только эти N строк». Проверено: 10 000 строк сидовой таблицы MySQL, MariaDB и PostgreSQL во всех форматах; потоковый XLSX открывает LibreOffice.

- [x] **V5.6** Перенос данных между подключениями (в том числе между разными СУБД) ⭐.
  «Скопировать в другое подключение…» — в дереве на таблице (выделенные вместе — все), папке «Таблицы», базе, схеме и подключении, в палитре: таблицы с галочками → подключение, база и схема назначения (то же место — отказ) → «Структура и данные» / «Только структура» / «Только данные» → что делать с таблицей, которая уже есть: «Заменить» (`DROP` и `CREATE`), «Добавить в неё строки» (в общие колонки) или «Оставить как есть» → окно-вопрос (read-only — отказ, production — `PRODUCTION`) → прогресс «таблица: N строк · таблица K из M» с отменой → итог и «Показать отчёт» (Markdown: по каждой таблице создана ли, сколько строк, ошибка и что не перенеслось).

Структура — `describeTable` → модель конструктора (`designFromStructure`) → перевод → `Dialect.ddl.createTable` цели. Перевод типов (`type-map.ts`) через нейтральный вид: целые по ширине и знаку (беззнаковые расширяются в PostgreSQL), `tinyint(1)`/`bit(1)` ↔ `boolean`, `decimal(p,s)`, `float`/`real`/`double` с учётом того, что `REAL` в PostgreSQL 4 байта, а в MySQL и SQLite 8, строки с длиной, длинный текст (`longtext` в MySQL, а для колонок в индексах — `varchar(255)`), даты и время с поясом и без, JSON, двоичные, UUID, `enum` (в PostgreSQL и SQLite — `text`), массивы и свои типы PostgreSQL — текст. Между СУБД одного вида типы не трогаются. Умолчания переводятся, если это литерал (без приведения `::type`), булево или текущее время (`CURRENT_TIMESTAMP(6)` для `datetime(6)` MySQL); прочие функции и `nextval` (serial становится автонумерацией) — в отчёт. Значения (`transfer-values.ts`): 0/1 ↔ булево, время с поясом в колонку без пояса — в UTC, текст в JSON-колонку и обратно. Внешние ключи — только к копируемым таблицам той же схемы; в MySQL и SQLite — внутри `CREATE TABLE`, в PostgreSQL (новое `DumpDialect.keysAfterData`) — `ALTER TABLE … ADD CONSTRAINT` после строк. Ошибка одной таблицы не останавливает остальные. Попутно исправлено: MySQL принимает умолчание у `TEXT`/`BLOB`/`JSON` только выражением в скобках — конструктор таблиц теперь пишет `DEFAULT ('…')` (`drivers/mysql/defaults.ts`). Проверено: сидовая база MySQL → PostgreSQL (вместе с таблицей всех типов и 10 000 строк), PostgreSQL → MySQL (свой enum-тип стал текстом), MySQL → SQLite (сначала структура, потом данные) → PostgreSQL, MySQL → MariaDB; внешние ключи работают, нумерация продолжается.

- [x] **V6.2** Microsoft SQL Server (`tedious`): метаданные, DDL, схемы, отмена.
  Новый драйвер `mssql` (SQL Server 2016+ и Azure SQL, вход по логину SQL Server): подключение к `host`, `host\INSTANCE` (через SQL Server Browser) или порту, TLS — `require` (шифрование без проверки), `verify-ca` (цепочка до своего CA, имя не важно — проверяется после рукопожатия, `tedious` сам так не умеет), `verify-full`; без TLS шифруется только вход, как у всех клиентов. Нет базы — понятное «не найдена» (первое сообщение сервера при входе, а не последнее «Login failed»). Сессия на базу, как у PostgreSQL (D28); запросы одной сессии — в своей очереди (`tedious` не принимает второй запрос, пока идёт первый), так что дерево и автодополнение ждут выполняемый запрос, а не падают. Отмена — attention в том же соединении; лимит строк и чтение с обратным давлением (`request.pause/resume`); состояние транзакции — со слов сервера (ENVCHANGE); затронутые строки — только операторов самого пакета, без того, что сделали триггеры; `PRINT` и предупреждения — в notice; ошибки — по номеру (208 → не найдено, 2627/547 → ограничение, `THROW` ≥ 50000 → ограничение), позиция — строка ошибки и имя из сообщения на ней.
  Точность значений (D66): `tedious` превращает DECIMAL и MONEY в число, а даты — в `Date` до миллисекунды; поэтому чтение значений этих типов перехвачено, и они разбираются прямо из байтов протокола в текст, как его пишет сервер: `decimal(38,0)` и `money` без потерь, `datetime2(7)`/`time(7)` со всеми 7 знаками, `datetimeoffset` в своём поясе (`2024-06-15 12:00:00.1234567 +03:00`), `datetime` с округлением сервера до .000/.003/.007. `bit` — булево, `tinyint` — 0…255.

Если пакет вернул несколько наборов строк, показывается первый (попутно исправлено и для `CALL` в MySQL: строки разных наборов больше не смешиваются под колонками первого). `BEGIN TRAN`/`SAVE TRAN`/`COMMIT` понимаются; голый `BEGIN` — блок, поэтому он не считается «только чтением»; safe mode видит `DELETE`/`DROP` и после `DECLARE`, `IF`, `BEGIN`, но не в теле создаваемой процедуры. Read-only в SQL Server проверяет только DataNest: у сервера нет read-only сессии. Ключевые слова, функции (`LEN`, `DATEADD`, `ISNULL`…), сниппеты (`MERGE`, `TOP`, процедура), форматирование диалектом `transactsql`, `схема.таблица` для перехода к определению.
  Метаданные из `sys.*`: базы (только доступные логину; `master`, `model`, `msdb`, `tempdb` — системные), схемы без ролевых, таблицы и представления, колонки с типом как в DDL (`nvarchar(50)`, `decimal(10,2)`, `datetime2(0)`), умолчания без скобок сервера (`((0))` → `0`), уникальные и внешние ключи (между схемами тоже), индексы с видом (`CLUSTERED`, фильтр), функции, процедуры, триггеры, последовательности; описания — `MS_Description`. Определения: представления, процедуры, функции и триггеры как написаны (`OBJECT_DEFINITION`; скрытое — «нет прав»), таблица собирается из каталогов — колонки с `IDENTITY`, вычисляемые, умолчания, `COLLATE`, ключи и `CHECK`, индексы с `INCLUDE` и `WHERE`, описания, внешние ключи, триггеры; имена, придуманные сервером (`PK__…`, `DF__…`), не пишутся. Документ определения и дамп ставят `GO` после каждого оператора.
  DDL: создание и удаление баз и схем (схема — только пустая), конструктор — `IDENTITY(1, 1)` (одна на таблицу, только у целых, без умолчания), описания через `sp_addextendedproperty`; изменение таблицы одной транзакцией: переименование колонок и таблицы через `sp_rename`, смена типа и `NULL` (`ALTER COLUMN`), умолчание находится и снимается по колонке, ключи, индексы, внешние ключи (`RESTRICT` → `NO ACTION`), описания добавляются, меняются и снимаются; добавить или снять `IDENTITY` у существующей колонки нельзя — понятный отказ. Замена определения — в транзакции (`DROP` + `CREATE`, а с `CREATE OR ALTER` — без `DROP`), ошибка оставляет прежний объект. Переименование, очистка, удаление из дерева.
  Остальное работает через общие механизмы: дамп (снимок `SNAPSHOT`, если база его разрешает, иначе по таблице; `IDENTITY_INSERT` для значений автонумерации; внешние ключи после строк; ключи других таблиц, которые указывают на удаляемые, снимаются первыми), выполнение файла, импорт, экспорт, генератор, перенос в другие СУБД и обратно (типы: `bit` ↔ boolean, `datetimeoffset` ↔ время с поясом, `nvarchar(max)`, `uniqueidentifier`, `money`; смещение пояса пишется полностью, `+03:00`), правка результата (сохранение внутри открытой транзакции — через `SAVE TRANSACTION`), табличный вид (`TOP`, а дальше `OFFSET … FETCH`; оценка строк по `sys.partitions`; фильтр без учёта регистра при любой сортировке колонки). Начало транзакции и точки сохранения теперь берутся из диалекта (`Dialect.transaction`, D67): голый `BEGIN` в T-SQL — блок. Форма подключения, URL `sqlserver://host:1433;databaseName=…;encrypt=true` (JDBC, Prisma) и `mssql://user@host/db`, импорт из `.env` (`DB_CONNECTION=sqlsrv`, порт 1433).
  Тестовый сервер — группа `mssql` (SQL Server 2022 в `docker/compose.yml`, порт 7143, свой entrypoint загружает `docker/seed/mssql` через `sqlcmd`, TLS с тестовым CA). Интеграционные тесты: драйвер (типы, ошибки, отмена, очередь, транзакции, метаданные, определения, TLS), дамп и восстановление на пустой базе (дважды), перенос SQL Server ↔ SQLite ↔ SQL Server, правка и табличный вид, конструктор и замена определений, файл с `GO`, импорт, экспорт, генератор. Страница (webview-приложение `schema-compare`, по панели на пару, D94): прогресс чтения источника и цели, счётчики «Новых / Различаются / Только в цели / Одинаковых», список по видам (таблицы, представления, функции, процедуры, триггеры, последовательности, события) с галочками — новые и изменённые отмечены сразу, удаления только по желанию, скрытые сервером определения не сравниваются и не попадают в скрипт. Выбранное различие: у таблицы — колонки (новая / удалена / изменена: тип, NULL, DEFAULT, автонумерация, комментарий), первичный ключ, индексы и внешние ключи, комментарий таблицы, пометки о том, чего скрипт не сделает (вычисляемые колонки, индексы по выражениям); у остальных — построчная разница определений (− цель, + источник); и его часть скрипта. «Поменять местами», «Обновить», «Открыть скрипт (N)» — скрипт выбранного открывается в новом редакторе на цели и ничего не выполняет сам.
  Сравнение (`services/schema-compare/`): таблицы — дизайны конструктора (`describeTable` → `designFromStructure`), дизайн источника «выравнивается» по целевому (колонки, индексы и ключи с тем же именем получают id цели, новые — свои, порядок колонок цели сохраняется), разница — `diffTables`, скрипт — `ddl.createTable` / `alterTable` / `dropRelation` того же диалекта, что у конструктора таблиц; остальные объекты — `getDefinition` (MySQL — без `DEFINER`), имя схемы источника в тексте заменяется именем цели по токенам (`public.f` → `staging.f`, строки и комментарии не трогаются), сравнение без учёта пробелов и комментариев перед `CREATE`. Порядок скрипта: изменённые и лишние представления, триггеры, функции удаляются до изменения таблиц и создаются после; новые таблицы — в порядке внешних ключей, удаляемые — в обратном; изменённая последовательность не пересоздаётся (её текущее значение пропало бы) — в скрипте комментарий с определением источника. Операторы записываются как в дампе (`GO` у SQL Server, `/` у Oracle, `DELIMITER` для тел MySQL); то, что диалект сделать не может, — комментарий с причиной.
  Тесты: unit — замена схемы в тексте (кавычки, регистр, строки, комментарии, вложенные имена), нормализация определений, построчная разница (общие строки, пустые тексты, CRLF, слишком большой текст), чтение снимка (таблицы, материализованные представления, скрытые и пропавшие определения, отмена), выравнивание дизайна, сравнение (новые, удалённые, изменённые, одинаковые, вычисляемые колонки, скрытые, цель для DROP), скрипт (заголовок, порядок создания и удаления таблиц, представлений, функций, триггеров, последовательности, завершение операторов, «нечего менять», часть одного различия, пометки), модель страницы (прогресс, колонки, ключи, комментарий, разница определений, скрипт выбранного, «поменять местами», ошибки), цель в дереве, протокол, страница; интеграция — на MySQL, MariaDB, PostgreSQL, SQLite и SQL Server полный круг: найденные различия, скрипт выполнен на цели, повторное сравнение не находит ни одного различия.
- [x] **V8.4** Сравнение данных двух таблиц ⭐.
  «Сравнить данные…» на таблице в дереве: она — источник, цель — таблица любого SQL-подключения (другая база, даже другая СУБД; таблица с тем же именем — первой в списке). Колонки сопоставляются по имени (точно, затем без учёта регистра), колонки только одной стороны перечислены; ключ — первичный ключ источника, иначе цели, иначе уникальный индекс; если общего ключа нет — выбор колонок, определяющих строку. Страница (webview-приложение `data-compare`, по панели на пару, D95): прогресс «Читаю цель / источник: N строк», «Остановить» (отменяет и запрос на сервере), «Одинаковых строк: N», вкладки «Различаются / Только в источнике / Только в цели» с числами; строки страницами по 200, NULL отдельно от текста, в изменённых клетках «цель → источник» с подсветкой, «Только различающиеся колонки». Скрипт синхронизации — галочки «Вставить недостающие», «Обновить различающиеся» (только изменённые колонки, по ключу цели), «Удалить строки, которых нет в источнике» (по умолчанию выключено), в транзакции, если она есть у СУБД цели; значения приведены к типу колонки цели правилами переноса V5.6 (`transferValue`: 1 → `TRUE` для boolean PostgreSQL и т. п.), вычисляемые колонки не пишутся; открывается в редакторе на цели и сам ничего не выполняет.
  Сравнение (`services/data-compare/`): цель читается в «ключ → 53-битный хеш значений» (число на строку, не строка), затем источник проверяется по этой карте (совпавший ключ помечается, а не удаляется — повтор ключа в источнике замечается без множества всех ключей), затем — только если нужно — цель читается ещё раз за значениями строк для показа; порядок строк и сортировка серверов не важны. Значения нормализуются для разных СУБД: числа (`10.50` = `10.5` = `1.05e1`, 64-битные точно), флаги (`true` = `1`), дата-время (`T`, нулевые доли и UTC — написание), JSON (порядок ключей), двоичные — по полным байтам, где они есть; строки сравниваются точно. Колонка, которая на одной из сторон JSON или дата (SQLite хранит их текстом), сравнивается как JSON или дата. Повтор значений ключа — понятная ошибка. Не больше 1 000 000 строк на сторону и 10 000 строк каждого вида для показа и скрипта (числа всегда точные, в скрипте — пометка «только первые N»).
  Тесты: unit — нормализация (числа, даты, JSON, двоичные, NULL, строки), ключи и хеши (разделитель, режимы колонок), сопоставление колонок и ключа (регистр, ключ цели, уникальный индекс, неполный ключ), типы и режимы колонок, сравнение (счёт, повторное чтение цели только при нужде, составной ключ, JSON-режим, предел хранимых строк, повторы ключа, отмена до начала и во время чтения с отменой на сервере, возврат сессий), скрипт (транзакция, приведение значений, вычисляемые колонки, обновление только изменённого, удаление, части по выбору, пометка о неполноте, `IS NULL`), модель страницы, протокол, страница; интеграция — MySQL → PostgreSQL (`DECIMAL`/`numeric(10,3)`, `BOOLEAN`/`boolean`, `DATETIME`/`timestamp`, лишняя колонка) и PostgreSQL → SQLite (составной ключ, 64-битное число, `jsonb`/`TEXT`): счёт, скрипт выполнен на цели — повторное сравнение без различий; повторяющийся ключ отвергается.
- [x] **V8.5** Мониторинг: список процессов, завершение запроса, переменные и статус сервера.
  «Монитор сервера» на SQL-подключении в дереве и в палитре открывает страницу (webview-приложение `server-monitor`, по панели на подключение, D96) со своей сессией: занятый редактор её не задерживает, закрытие страницы закрывает сессию. Сверху — сервер и версия, карточки «Работает», «Подключения N / предел», «Запросов/с» или «Транзакций/с» (разница двух чтений), «Размер» базы; «Авто» с интервалом 2/5/10/30 с (по умолчанию включено, 5 с) и «Обновить». Вкладки: «Процессы (N)» — ID, пользователь, хост, база, состояние (с ожиданием и «ждёт N» у заблокированных), время, запрос; самые долгие сверху, сортировка щелчком по колонке, фильтр по любому тексту, «Скрыть бездействующие» (своя сессия помечена «(эта страница)» и не скрывается); выбранный процесс — с полным текстом запроса внизу, «Отменить запрос» и «Завершить сеанс» — модальный вопрос с пользователем и началом запроса (у production — пометка), на read-only подключении — отказ, свою сессию остановить нельзя; процесс, который уже закончился, — «уже завершился». «Переменные» — сеанс и сервер (глобальные / кластер / сервер / система — как называет СУБД), значение с единицей, описание, «Только изменённые». «Статус» — счётчики сервера с группой и «В секунду» для изменившихся чисел, «Только меняющиеся».
  По СУБД (`services/monitor/`, сервер определяется как в V8.2): MySQL, MariaDB, TiDB — `information_schema.PROCESSLIST`, `KILL QUERY` / `KILL CONNECTION`, `SHOW SESSION|GLOBAL VARIABLES`, `SHOW GLOBAL STATUS`; PostgreSQL и YugabyteDB — `pg_stat_activity` (клиентские процессы, кто блокирует — только у ждущих блокировку), `pg_cancel_backend` / `pg_terminate_backend`, `pg_settings` (единицы, описание, изменённые — по `source`), сумма `pg_stat_database` и `pg_stat_bgwriter`; CockroachDB — `crdb_internal.cluster_sessions` с запросами `cluster_queries`, `CANCEL QUERY` / `CANCEL SESSION`, `SHOW ALL` и `SHOW CLUSTER SETTINGS`, `crdb_internal.node_metrics`; SQL Server — `sys.dm_exec_sessions` с запросами и текстом последнего пакета, `KILL` (только сеанс целиком), `DBCC USEROPTIONS` и `sys.configurations` (ждущие RECONFIGURE — изменённые), счётчики экземпляра `dm_os_performance_counters`; ClickHouse — выполняющиеся запросы `system.processes` (без самого списка), `KILL QUERY … ASYNC`, `system.settings` и `system.server_settings`, `metrics`, `events`, `asynchronous_metrics`; Oracle — `V$SESSION` с текстом из `V$SQL`, `ALTER SYSTEM CANCEL SQL` / `KILL SESSION … IMMEDIATE`, `V$PARAMETER` / `V$SYSTEM_PARAMETER`, `V$SYSSTAT`; SQLite — без процессов: прагмы соединения и страницы файла. Redis — своя страница «Информация о сервере» (V7.4); MongoDB и Elasticsearch — в бэклоге.
  Найдено и исправлено по дороге: драйвер MySQL ждал вечно, если сервер обрывал сессию во время запроса (mysql2 сообщает об этом соединению, а не запросу без колбэка) — теперь запрос и следующие сразу получают `connection-failed`; `KILL SESSION` Oracle отвечает ORA-00031 «помечена на завершение», и тонкий драйвер считал это обрывом *своего* соединения — команда идёт в PL/SQL-блоке, где -31 — успех.
  Тесты: unit — сервер и его возможности, чтение процессов каждой СУБД (простои, блокировки, свои, повторы сессий, обрезка текста, отказы), команды остановки (формы id, кавычки, что сервер не умеет), проверка наличия до `KILL`, переменные каждой СУБД (единицы, изменённые, сортировка, прагмы, которых нет в сборке), статус и сводка каждой СУБД, строки по именам колонок, модель страницы (сервер, ошибка подключения, скрытый id запроса, области переменных, скорость между чтениями, перезапуск сервера, политика остановки, одна очередь, работа после ошибки), протокол, функции страницы, страница (сводка, фильтры, сортировка, остановка, read-only, вкладки, автообновление); интеграция на MySQL, MariaDB, PostgreSQL, SQLite, SQL Server, ClickHouse, Oracle, TiDB, CockroachDB и YugabyteDB — свой процесс, чужой запрос по метке найден и отменён (сессия жива), чужой сеанс завершён и пропал из списка, остановка исчезнувшего, переменные обеих областей, статус и счётчик скорости; MySQL-драйвер — обрыв сессии сервером во время запроса; e2e — страница открывается одна на подключение.
- [x] **V8.6** Пользователи и права: просмотр, создание, `GRANT`/`REVOKE` с предпросмотром.
  «Пользователи и права» на SQL-подключении или базе в дереве и в палитре открывают страницу (webview-приложение `user-admin`, по панели на подключение и базу, D97) со своей сессией. - [x] **V8.7** Графики по результату запроса (line/bar/pie) ⭐.
  Кнопка «График» в панели результатов (у результата с колонками) и команда «График по результату» в палитре (результат SQL-редактора, даже если фокус в панели результатов) открывают рядом вкладку графика (webview-приложение `result-chart`, по панели на результат, D98). Первый вариант угадывается по колонкам: подписи — первая колонка даты/времени, иначе первая текстовая; значения — числовые колонки (до 8 серий); по времени или числам — линии, одно значение и немного подписей — круговая, иначе столбцы; нет чисел — число строк по подписям. Переключатели: «Линии / Столбцы / Круговая», «Подписи (X)», «Значения (Y)» (только числовые колонки; у круговой — одна), «Одинаковые подписи» — по точке на строку, сумма, среднее, число строк, минимум, максимум. Линии — ось X по значению, если все подписи — числа или даты (промежутки видны), разрыв линии на пустом значении, точки при ≤ 60 подписях; столбцы — группами от нуля (отрицательные вниз); круговая — самые большие секторы, остальное в «Прочее», доли на секторах и в легенде. ## V9 — Стабилизация (0.9.0)

- [x] **V9.1** Бюджет производительности: время активации, 1M строк в таблице, потребление памяти. Замеры в CI.
  Замеры (`npm run test:perf`, `test/perf/`, бюджеты — в `test/perf/budgets.ts`, D99): размеры бандлов production-сборки (`extension.js` ≈ 720 КБ из 1 МБ, самый большой драйвер, самое большое webview-приложение), загрузка `dist/extension.js` с заглушкой `vscode` (медиана 5 запусков в отдельном Node), миллион строк в host — память на строку, окно таблицы, сортировка по числам, decimal, датам, повторяющемуся тексту с NULL и по уникальному тексту, поиск — и для каждой сортировки и поиска «самая долгая занятость host»; миллион строк через драйвер SQLite production-сборки (время, память). Первая активация в настоящем VS Code меряется в e2e корневым хуком до всех наборов (локально ≈ 120 мс, бюджет 1 с), пишется в лог e2e и в сводку задачи; расширение само пишет в Output «activated … in N ms». В CI — задача «Performance budget»: таблица «замер / значение / бюджет / доля» в сводке задачи, превышение — ошибка с аннотацией.
  Найдено замерами и исправлено: сортировка миллиона строк по тексту шла **85 с**, по дате 50 с, по e-mail 45 с, по decimal 8 с — весь этот срок extension host стоял (а страница через 30 с получала тайм-аут RPC). Причина — на каждое из ~20 млн сравнений заново считались текст ячейки, регулярное выражение, `Number()` и `localeCompare` с опциями. Теперь (`shared/cell-compare.ts`) ключи колонки считаются один раз в типизированные массивы (вид, число, «влезает в double» — точные числа до 15 цифр сравниваются как double, длинные — по цифрам), каждый различный текст упорядочивается один раз одним `Intl.Collator`, строки сравнивают ранги; сортировка — своя устойчивая сортировка слиянием (`shared/merge-sort.ts`) шагами, которые прерываются паузой каждые 20 мс. Итог на 1M строк: числа 0,45 с, decimal 0,8 с, даты 0,9 с, уникальный текст ≈ 7–9 с (цена ICU), host не занят дольше ~90 мс подряд. Порядок прежний (те же правила: NULL в конце в обе стороны, булевы, точные числа, числа перед текстом, текст как читает человек); отсутствующая ячейка теперь — NULL и при убывании. Новая сортировка обгоняет незаконченную старую, а замена строк после сохранения отменяет её.
  Поиск по результату шёл на каждое нажатие клавиши и на миллионе строк держал host ~1 с за раз; теперь он тоже идёт частями, более новый поиск того же результата (а также сортировка, новые строки, закрытие) останавливает старый, страница отбрасывает ответ на уже изменённый текст. Память: все результаты вместе держат не больше 20 млн ячеек (`MAX_KEPT_CELLS`, ≈ 1 ГБ) — раньше 20 запусков по миллиону строк на документ могли уронить extension host; сверх предела удаляются самые старые результаты любых документов, кроме самого нового и результатов с несохранёнными правками. Таблица: миллион строк × 22 px укладывается в предельную высоту элемента Chromium (проверено тестом), в DOM — несколько десятков строк. Драйвер SQLite: 1M строк ≈ 3 с, размер пачки (200 / 1000) не влияет — время уходит на сам SQLite и передачу между потоками.
  Тесты: unit — сортировка слиянием (размеры вокруг длины прогона, устойчивость на повторах, уже упорядоченные и обратные, паузы только на большом, несогласованный компаратор, паузы по часам, ошибка изнутри), сравнение (decimal длиннее double против числа, отрицательные и нули, числа текстом, экспонента, неразличимые для collator тексты, смешанная колонка всех видов, отсутствующая ячейка при убывании, порядок частями = обычному, паузы, согласие с попарным сравнением), поиск частями (= обычному, паузы, остановка устаревшего), хранилище (обгон сортировки, результат удалён во время сортировки, строки заменены, строки читаются во время сортировки, миллион строк без долгой занятости host, предел ячеек: старые любого документа, ячейки а не строки, новейший остаётся, правки не теряются, события документам, оставшиеся результаты документа; поиск: обгон, новые строки, закрытие, независимость результатов), страница (миллион строк — десятки строк в DOM и одно окно, ответ устаревшего поиска не затирает новый), геометрия (предельная высота, экран строк в любом месте), раскладка `test/` (`test/perf`), задача CI; e2e — бюджет первой активации; perf — все замеры выше.
