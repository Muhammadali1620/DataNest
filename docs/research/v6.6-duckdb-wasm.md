# V6.6 — DuckDB без нативных модулей

Дата: 2026-10-29. Итог: **в бэклог** (так и записано в шаге: «если найдётся вариант без нативных модулей (WASM), иначе — в бэклог»).

## Вопрос

Официальные клиенты DuckDB для Node (`duckdb`, `@duckdb/node-api`) — нативные модули, а нативный код запрещён (принцип 5). Остаётся DuckDB-WASM (`@duckdb/duckdb-wasm`): у него есть сборка для Node (`duckdb-node-blocking.cjs`). Может ли она быть драйвером — открывать `.duckdb`-файлы пользователя, писать в них и читать их снова?

## Как проверяли

Зонд [`scripts/research/duckdb-probe/probe.cjs`](../../scripts/research/duckdb-probe/probe.cjs) на `@duckdb/duckdb-wasm@1.33.1-dev57.0` (DuckDB v1.5.4; у пакета все выпуски помечены `-dev`), Node 22, Linux x64:

```sh
npm install --prefix /tmp/duck @duckdb/duckdb-wasm@1.33.1-dev57.0
node scripts/research/duckdb-probe/probe.cjs /tmp/duck /tmp/duck-files
```

## Результаты

| Проверка | Итог |
|---|---|
| Запуск движка (`instantiate`) | ✅ ~0,8 с |
| Запрос в памяти (`range(100000)`) | ✅ |
| Открыть файл по пути и записать таблицу | ⚠️ запрос проходит, файл на диске появляется (540 КБ) |
| Открыть тот же файл снова (новый экземпляр) | ❌ «database does not exist» |
| Новый файл через `registerFileURL(…, NODE_FS)` | ❌ «exists, but it is not a valid DuckDB database file» |
| Прочитать записанный файл через `NODE_FS` | ❌ «database does not exist» |
| Размер движка | 36 МБ WASM (`duckdb-eh.wasm`), ещё 33–41 МБ у двух других сборок, плюс `apache-arrow` |

## Вывод

Сборка для Node работает только с базой в памяти: свой файл она пишет в формате, который потом сама не открывает, а настоящие файлы через `NODE_FS` не открывает вовсе. Клиент, который не открывает `.duckdb`-файлы пользователя, не нужен; к тому же расширение выросло бы на десятки мегабайт. Шаг V6.6 перенесён в бэклог с условием: вернуться, когда DuckDB-WASM начнёт открывать локальные файлы в Node (или у DuckDB появится клиент без нативного кода) — зонд выше покажет это за минуту.
