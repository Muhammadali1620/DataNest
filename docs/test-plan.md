# Ручной тест-план

Прогоняется перед каждым релизом в трёх редакторах: **VS Code**, **VSCodium**, **Cursor**.
Автотесты (`npm test`, `npm run test:integration`, `npm run test:e2e`) должны быть зелёными до начала.

Отметки: `✅` работает · `⚠️` работает с замечанием · `❌` сломано (баг + тест по правилу 7 из ARCHITECTURE §11).

## Подготовка

```sh
npm ci
npm run db:up          # группа core: MySQL 7306, MariaDB 7307, PostgreSQL 7432, SSH 7022
npm run db:up -- mssql # SQL Server 7143 (раздел 16a)
npm run db:up -- clickhouse # ClickHouse 7123/7443 (раздел 16b)
npm run db:up -- oracle # Oracle 23ai Free 7521 (раздел 16c)
npm run db:up -- compat # TiDB 7400, CockroachDB 7257, YugabyteDB 7533 (раздел 16d)
npm run package        # соберёт datanest-<версия>.vsix
```

Поставить `.vsix` в каждый редактор: «Extensions: Install from VSIX…».
Перед прогоном в новом редакторе удалить прежнюю версию и перезапустить его.

Подключения для прогона (пароль у всех `datanest`, пользователь `datanest`, база `datanest_test`):

- MySQL — `127.0.0.1:7306`
- MariaDB — `127.0.0.1:7307`
- PostgreSQL — `127.0.0.1:7432`
- SQLite — новый файл через «Новый файл…» в форме

## 1. Активация

1. Открыть редактор без единого подключения → иконка DataNest есть в Activity Bar.
2. Открыть вид DataNest → видно приглашение создать подключение, расширение активировалось (в «Output → DataNest» строка `DataNest <версия> activated`).
3. Команда «DataNest: Show Logs» открывает канал.
4. В палитре нет служебных команд: «Open Ping Page», «Run This Statement», «Open Table».

## 2. Подключения

1. «New Connection» → форма открылась вкладкой.
2. Тип MySQL: порт подставился 3306, сменить на 7306, заполнить хост/пользователя/пароль/базу.
3. «Проверить подключение» → «Подключение работает».
4. Ввести неверный пароль → «Проверить подключение» показывает сообщение сервера, а не стек.
5. Сохранить → подключение появилось в дереве.
6. Повторить для MariaDB и PostgreSQL.
7. SQLite: выбрать тип → поля хоста/порта исчезли, появился выбор файла. «Новый файл…» → сохранить `~/datanest-demo.db` → сохранить подключение.
8. Изменить подключение: открыть форму, увидеть подсказку «Пароль сохранён», сохранить без ввода пароля → подключение по-прежнему работает.
9. Дублировать подключение → копия с именем «… (copy)» и рабочим паролем.
10. Удалить копию → подтверждение, затем исчезает из дерева.
11. Перезапустить редактор → подключения на месте, пароли не потерялись.

## 3. Дерево

1. Раскрыть MySQL → подключение стало зелёным, видны базы `datanest_test` и `datanest_empty`.
2. Системных баз (`information_schema`, `mysql`, `performance_schema`, `sys`) не видно.
3. Включить `datanest.showSystemObjects` → они появились без переподключения; выключить обратно.
4. `datanest_test` → «Таблицы» и «Представления»; в таблицах — `customers`, `orders`, `big_table`, в представлениях — `order_totals`.
5. Раскрыть `customers` → колонки с типом, `PK` у `id`, `NOT NULL` где положено, `DEFAULT` у `created_at`.
6. PostgreSQL: база → схемы (`public` сверху), `pg_catalog` и `information_schema` скрыты.
7. SQLite: под подключением сразу «Таблицы»/«Представления», без уровня баз.
8. «Копировать имя» на таблице и на колонке → в буфере имя.
9. «Обновить» на подключении → дерево перечитывается (создать таблицу в `psql` и убедиться, что она появилась только после «Обновить»).
10. «Отключиться» → значок погас, при следующем раскрытии подключается снова.
11. Остановить Docker (`npm run db:down`) и раскрыть узел → ошибка показана листом, дерево не сломано. Поднять обратно (`npm run db:up`).

## 4. Редактор SQL

1. «Новый запрос» из заголовка вида → пустая вкладка SQL, в статус-баре «Выбрать подключение».
2. Выбрать подключение и базу → в статус-баре имя и база.
3. «Новый запрос» из контекстного меню базы → документ сразу привязан к ней.
4. Набрать `SEL` → автодополнение предлагает `SELECT`.
5. `SELECT * FROM ` → предлагаются таблицы; `SELECT c. FROM customers c` → предлагаются колонки.
6. Внутри строки `'…'` и после `--` подсказок нет.
7. Над каждым запросом есть «▶ Run».
8. `Ctrl+Enter` на запросе под курсором → выполняется только он.
9. Выделить два запроса → `Ctrl+Enter` выполняет оба (две вкладки результатов).
10. `Ctrl+Shift+Enter` → выполняется весь файл.
11. Скрипт с `DELIMITER //` и процедурой выполняется целиком, тело не разрезано.
12. PostgreSQL: функция с телом `$$ … $$` выполняется целиком.

## 5. Выполнение и отмена

1. `SELECT SLEEP(10)` (MySQL) → в статус-баре счётчик времени, в заголовке редактора кнопка «Отменить».
2. Нажать «Отменить» → запрос останавливается за секунду-две, редактор снова свободен.
3. Отменить из панели результатов кнопкой «Отменить» → тот же результат.
4. Поставить `datanest.queryTimeout` = 3, выполнить `SELECT SLEEP(10)` → через 3 с результат с ошибкой «timeout» и упоминанием настройки. Вернуть 0.
5. `SELECTT 1` → ошибка с текстом сервера, «на символе N» и ссылкой «Перейти к ошибке» — курсор встаёт на место ошибки.
6. Скрипт из трёх запросов, где второй с ошибкой → первая вкладка с данными, вторая с ошибкой, третий не выполнялся.
7. `INSERT`/`UPDATE`/`DELETE` во временную таблицу → «затронуто строк».

## 6. Таблица результатов

1. `SELECT * FROM big_table` (10 000 строк) → при лимите 1000 видно предупреждение об обрезке.
2. Поставить `datanest.rowLimit` = 10000, выполнить снова → прокрутка до конца плавная, редактор не подвисает.
3. Заголовок и номера строк остаются на месте при прокрутке вниз и вправо.
4. Потянуть границу колонки → ширина меняется за указателем; двойной клик по границе — подгон по заголовку.
5. `NULL` отличается от строки `NULL` (курсив, серый).
6. Клик по ячейке, протягивание мышью, `Shift+стрелки`, `Ctrl+A` → выделение ведёт себя ожидаемо.
7. `Ctrl+C` на диапазоне → вставить в LibreOffice Calc / Excel / Google Sheets: столбцы и строки не разъехались, значение с переводом строки осталось в одной ячейке.
8. Клик по заголовку: по возрастанию → по убыванию → исходный порядок. `NULL` всегда в конце.
9. Поиск: ввести `example.com` → «1 из N», Enter и Shift+Enter ходят по совпадениям, найденная строка выделяется и прокручивается.
10. Несколько запросов → переключение вкладок сохраняет содержимое каждой.
11. CSV: кнопка «CSV» → сохранить файл → открыть: заголовок на месте, значения с запятыми и кавычками корректны, `BIGINT` не округлён.
12. JSON: кнопка «JSON» → в файле массив объектов, точные числа строками, JSON-колонка вложена как объект.

## 7. Просмотр таблицы

1. Контекстное меню таблицы → «Открыть таблицу» → страница данных и «строки 1–200 из N».
2. «Вперёд»/«Назад» листают, диапазон меняется, на последней странице «Вперёд» недоступно.
3. Изменить `datanest.pageSize` на 50 → открыть таблицу заново → страницы по 50.
4. Открыть представление `order_totals` → данные показаны так же.
5. Открыть пустую таблицу → «строки 0–0 из 0», без ошибок.

## 8. Редактирование данных (0.2.0)

1. `SELECT * FROM customers` → в панели значок «Можно редактировать»; `SELECT * FROM order_totals` и запрос с `JOIN` → «Только чтение», в подсказке причина.
2. Двойной клик / Enter / F2 по ячейке → редактор по типу: число, текст, дата (`<input type=date>`), bool и enum — список. Esc отменяет, Delete ставит NULL, кнопка DEFAULT ставит умолчание.
3. Ввести `abc` в числовую колонку → отказ с причиной, значение не меняется.
4. Insert — новая строка (зелёная), «Дублировать» копирует строку без ключа, Ctrl+Delete помечает выделенные строки зачёркнутыми, «Вернуть» снимает пометку.
5. «Предпросмотр SQL» → в новом редакторе транзакция DELETE → UPDATE → INSERT; «Сохранить» (Ctrl+S) → изменения в базе, сгенерированные ключи видны после перечитывания.
6. Удалить строку в другом клиенте и сохранить её правку здесь → понятная ошибка, откат, очередь правок осталась.
7. F4 — панель значения: JSON форматируется и подсвечивается, `attributes` в `products`; бинарная колонка — hex; PNG в BLOB — картинка.
8. Shift+F4 — карточка записи: поля по типам, Enter отправляет, Shift+Enter — новая строка в тексте, правка попадает в ту же очередь.

## 9. Фильтр, страницы, колонки (0.2.0)

1. Открыть `big_table` → «Фильтр»: `value_mod` равно `5` → 100 строк, счётчик пересчитан; «содержит» `row-0001` → строки с этим текстом.
2. Свой `WHERE`: `id < 10` → 9 строк; `id < 10; DROP TABLE x` → отказ.
3. Клик по заголовку в табличном виде → сортировка на сервере (видна в порядке всех страниц, не только первой).
4. Страницы: «Строк на странице» 50, поле «Страница N из M» + Enter, «Загрузить всё» на большой таблице спрашивает подтверждение.
5. Большая таблица без фильтра → число строк «примерно», кнопка точного подсчёта даёт `COUNT(*)`.
6. В `orders` ячейка `customer_id` помечена ↗: Ctrl+клик / F12 → открывается `customers`, отфильтрованная по этой строке.
7. «Колонки»: скрыть колонку, закрепить 📌 (остаётся на месте при прокрутке вправо), «По содержимому», «Сбросить»; вид сохраняется при листании страниц.

## 10. Копирование, экспорт, история, safe mode (0.2.0)

1. Выделить диапазон → «Копировать как…» каждый формат: TSV, CSV, JSON, Markdown, INSERT, UPDATE, `IN (…)` → вставить в редактор, текст корректный, `BIGINT` не округлён.
2. «Выгрузить как…» → SQL, Markdown, XLSX: файл `.xlsx` открывается в LibreOffice/Excel, `0042` и 19-значные числа остались текстом.
3. «История запросов» (значок в заголовке редактора): поиск по словам, «Запустить снова», «Копировать SQL», «Удалить», фильтр по подключению, «Очистить».
4. Запрос с `IDENTIFIED BY 'secret'` → в истории `***`, «Запустить снова» открывает его без запуска.
5. `DELETE FROM big_table` → модальное подтверждение со списком; `datanest.safeMode` = `block` → запуск запрещён; `off` → без вопроса. `DELETE … WHERE` — без вопроса.

## 11. Структура БД (0.3.0)

1. Раскрыть базу MySQL `datanest_test` → папки «Функции» (`order_total`), «Процедуры» (`customer_orders`), «События»; у `order_items` — «Индексы», «Внешние ключи», «Триггеры» (`order_items_quantity_check`). В PostgreSQL — «Последовательности» (`invoice_number_seq`), у функций видны аргументы.
2. «Показать DDL» у таблицы, представления, функции, триггера, последовательности → новый редактор с выполнимым скриптом (у процедуры MySQL — `DELIMITER //`).
3. «Новая база данных…» / «Удалить базу данных…» (PostgreSQL, с вводом имени), «Новая схема…», «Удалить схему…» (только пустую / CASCADE): каждый раз модальное окно с SQL и кнопками «Выполнить» / «Открыть в редакторе».
4. «Переименовать…», «Очистить таблицу (TRUNCATE)…», «Удалить…» у таблицы и представления; у SQLite «Переименовать» представление — понятный отказ.
5. «Найти объект базы…» (🔍 в заголовке панели): ищется по имени и по месту, таблица открывает данные, функция — DDL; пункт «Подключиться к … и искать там».

## 12. Конструктор таблиц (0.3.0)

1. «Новая таблица…» на базе → конструктор: колонка `id` с автонумерацией; добавить колонки (тип с подсказками, длина, NOT NULL, умолчание, комментарий), поменять порядок ▲▼; вкладка SQL показывает `CREATE TABLE`.
2. Ошибки: пустое имя, повтор имени колонки (сразу), автонумерация у `varchar` → сообщение; «Сохранить» (Ctrl+S) → окно с SQL → после выполнения таблица в дереве, конструктор переходит в режим правки.
3. Вкладки «Индексы» (колонки чипами, порядок важен, «уникальный») и «Внешние ключи» (таблица-цель из списка, колонки цели, ON DELETE/UPDATE, ключ на саму себя).
4. «Изменить таблицу…» у существующей: переименовать колонку, сменить тип, добавить и удалить колонку, сменить ключ, добавить индекс → SQL `ALTER` (MySQL — минимальные `CHANGE … AFTER`, PostgreSQL — транзакция, SQLite — пересоздание с заметкой), «Вернуть как было», «Изменений пока нет». В PostgreSQL кнопок перестановки нет.
5. Таблица с индексом-выражением или `FULLTEXT` → строка «остаются как есть», после `ALTER` индекс на месте.

## 13. Редактирование объектов и шаблоны (0.3.0)

1. «Изменить определение…» у процедуры MySQL → поправить тело → линза «✓ Применить» / кнопка в заголовке → окно с SQL (проба под временным именем, `DROP`, `CREATE`) → процедура изменена.
2. Сломать синтаксис и применить → ошибка, процедура прежняя (проверить `CALL`), временной копии нет.
3. То же для функции PostgreSQL, представления, материализованного представления (индекс остался) и триггера SQLite.
4. «Сгенерировать SELECT / INSERT / UPDATE / DELETE» у таблицы → редактор со сниппетом, Tab проходит по значениям; у представления — только SELECT.

## 14. Редактор SQL (0.3.0)

1. «Format Document» на документе с несколькими запросами и `DELIMITER` → запросы отформатированы, разделители и комментарии между ними на месте; `datanest.format.keywordCase` = `lower` меняет регистр.
2. Автодополнение: в `SELECT | FROM orders o JOIN customers c ON …` колонки обеих таблиц с подписью `o` / `c`, алиасы; после `big.` в `WITH big AS (SELECT id, total …)` — `id`, `total`; функции вставляются вызовом с аргументами; в начале запроса — сниппеты `sel`, `ins`, `upsert`.
3. Наведение на таблицу → колонки с типами, ключами, комментарием; на `o.total` → тип, умолчание, комментарий колонки; F12 на таблице или вызове функции → DDL только для чтения, курсор на имени.
4. Ошибочный запрос (`SELECT id, FROM customers`, `SELECT emial FROM customers`) → красное подчёркивание на нужном слове и строка в «Проблемах» (MySQL, PostgreSQL, SQLite); новая правка текста снимает отметку.

## 15. Подключения pro (0.4.0)

`npm run db:up` поднимает и SSH-сервер `datanest-ssh` (`127.0.0.1:7022`, пользователь `datanest`, пароль `datanest`; ключ — `test/fixtures/ssh/id_ed25519`, passphrase `datanest-key`). Базы за ним называются `mysql:3306`, `mariadb:3306`, `postgres:5432`.

1. Новое подключение PostgreSQL на хост `postgres`, порт `5432`, `datanest`/`datanest`, «Подключаться через SSH-туннель»: `127.0.0.1`, `7022`, `datanest`, пароль `datanest` → «Проверить» спрашивает про ключ сервера (виден отпечаток `SHA256:…`), «Доверять и подключиться» → «Подключение работает». Повторная проверка больше не спрашивает.
2. Тот же сервер с входом по ключу (файл через «Обзор…», passphrase `datanest-key`); без passphrase — понятная ошибка «ключ защищён паролем».
3. Сохранить, открыть заново: SSH-пароль не показан, есть подсказка «сохранён». Раскрыть подключение, выполнить запрос, отменить долгий `SELECT pg_sleep(30)`.
4. Хост БД `no-such-db` → ошибка «SSH-сервер … не может достучаться до no-such-db:3306».
5. Jump host: SSH-сервер `ssh-inner`, порт `22`, вход ключом (passphrase `datanest-key`), «Добавить промежуточный хост» → `127.0.0.1`, `7022`, `datanest`/`datanest` → «Проверить» спрашивает про ключи обоих серверов и подключается; в подсказке подключения в дереве весь маршрут. Без jump-хоста `ssh-inner` недоступен.
6. SSL/TLS (сертификаты — в `docker/tls`): PostgreSQL `127.0.0.1:7432`, «Шифровать, проверять издателя и имя хоста», CA `docker/tls/ca.crt` → «Подключение работает», `SELECT ssl FROM pg_stat_ssl WHERE pid = pg_backend_pid()` → `true`. С `other-ca.crt` — ошибка «не доверен». Без CA — тоже «не доверен» (тестовый CA не системный).
7. Клиентский сертификат: пользователь `datanest_cert` (MySQL — пароль `datanest`, PostgreSQL — без пароля), сертификат `client.crt`, ключ `client.key` → подключается; без них — отказ. Только сертификат без ключа — форма не сохраняет.
8. TLS через SSH: хост `postgres-alias` через туннель с `verify-full` → «сертификат не выдан для "postgres-alias"», с `verify-ca` — подключается; хост `postgres` с `verify-full` — подключается.
9. URL: в форме вставить `postgres://datanest:datanest@127.0.0.1:7432/datanest_test?sslmode=require` → «Заполнить» → поля, пароль и TLS заполнены, «Проверить» работает. Команда «Добавить подключение по URL…» с тем же URL → форма заполнена, под паролем «пароль из URL будет сохранён»; после сохранения и повторного открытия пароль сохранён.
10. `.env`: в папке проекта файл `.env` с `DATABASE_URL=mysql://datanest:datanest@127.0.0.1:7306/datanest_test` и `PGHOST=127.0.0.1`, `PGPORT=7432`, `PGUSER=datanest`, `PGPASSWORD=datanest`, `PGDATABASE=datanest_test`, рядом `.env.example` → «Импортировать подключения из .env…» показывает два подключения (из `.env.example` — нет), после добавления оба подключаются; повторный импорт помечает их «уже сохранено».
11. Папки: «…» → «Новая папка…» → `Prod`; перетащить в неё два подключения (выделить оба с Ctrl), перетащить одно перед другим, папку — выше другой папки; «Переместить в папку…» → «Без папки». Перезапустить редактор — порядок тот же. «Удалить папку» у непустой — вопрос, подключения остаются.
12. «Цвет…» → «Красный»: имя подключения красное с точкой, иконка по-прежнему показывает статус (зелёная после подключения); у баз внутри цвета нет. Светлая и тёмная тема. В форме подключения «Цвет» и «Папка» показывают то же.
13. Production: у подключения MySQL включить «Рабочая (production) база» → в дереве красное имя, бейдж «P», «Production» в описании; в редакторе строка состояния `PROD` на красном. `SELECT 1` выполняется без вопросов, `UPDATE … WHERE id = 1` — одно окно «Это изменит рабочую базу» со списком; `DELETE FROM t` без WHERE — то же окно с пометкой safe mode, без второго вопроса. Правка ячейки → «Сохранить» → вопрос. «Новая таблица…»/«Удалить…» → в заголовке окна «PRODUCTION».

Запись без `host` — строка «пропущено: host-empty», остальные работают.

Переименовать подключение в файле руками → пароль не теряется (тот же `id`). Перетащить проектное подключение в папку — ничего не происходит.
18. «Manage Workspace Trust» → «Не доверять» → узел проекта говорит «Ограниченный режим…», подключений нет; «Доверять» → появились.
19. Транзакции: в редакторе на PostgreSQL в строке состояния «Автофиксация»; кликнуть → «Ручная фиксация». `UPDATE … WHERE id = 1` → жёлтое «Транзакция открыта», «Commit», «Rollback»; из второго редактора изменения не видно. «Rollback» → значение прежнее, индикатор снова «Ручная фиксация». То же с «Commit» → изменение видно из второго редактора. `SELECT` в ручном режиме транзакцию не открывает.
20. PostgreSQL: в открытой транзакции `SELECT 1/0` → красное «Транзакция сорвалась», только «Rollback». MySQL: в открытой транзакции `CREATE TABLE x (id int)` → вопрос «MySQL зафиксирует открытую транзакцию»; «Отмена» — ничего не выполнилось.
21. Открытая транзакция: «Выбрать подключение» в строке состояния → вопрос «Зафиксировать / Откатить»; «Отключить» в дереве → «в 1 редакторе открыта транзакция»; закрыть редактор → предупреждение «откачена». В автофиксации написать `BEGIN;` руками → индикатор тоже показывает открытую транзакцию.
22. Сетка в редакторе с открытой транзакцией: правка ячейки → «Сохранить» → сообщение «изменения вошли в открытую транзакцию»; «Rollback» в строке состояния отменяет и их.
23. Сессия: у MySQL раскрыть «Сессия: …», часовой пояс `+03:00`, init SQL `SET @x = 5` → «Проверить» работает; в редакторе `SELECT @@session.time_zone, @x` → `+03:00`, `5`. Пояс `Mars/Base` → «Проверить» говорит «сервер отверг часовой пояс». Кодировка `latin1` → `SELECT 'café'` возвращает `café`. У PostgreSQL поля «Кодировка» нет, у SQLite — только таймаут запроса и init SQL (`PRAGMA foreign_keys = ON` → `PRAGMA foreign_keys` = 1).
24. Таймаут запроса подключения 2 с → `SELECT SLEEP(5)` отменяется через 2 с с сообщением о таймауте, даже если `datanest.queryTimeout` = 0. Таймаут подключения 2 с на хост `10.255.255.1` → ошибка примерно через 2 с.
25. Keep-alive 10 с → в логах (уровень debug) / `SHOW PROCESSLIST` видно, что простаивающая сессия делает `SELECT 1` раз в 10 с; в read-only подключении init SQL `SET SESSION TRANSACTION READ WRITE` — подключение не открывается, ошибка это объясняет.
26. Фильтр: у MySQL «Фильтр баз данных…» → снять галочку с одной базы → её нет в дереве, внизу «Ещё 1 скрыто фильтром», в подсказке подключения — `Базы: …`. «Задать шаблонами…» → `datanest_*, !datanest_empty` → видна только `datanest_test`. Поиск объектов (🔍) не находит таблиц скрытых баз. Отметить всё → фильтр снят. У PostgreSQL на схеме «Фильтр схем…» → снять `inventory` → схема пропала во всех базах. В форме раздел «Видимые базы и схемы» показывает те же шаблоны.
27. Экспорт: «…» → «Экспортировать подключения…» → снять одну галочку → сохранить файл → в нём нет id, паролей и снятого подключения, есть `folders`. Удалить одно из экспортированных подключений → «Импортировать подключения…» → этот файл → удалённое отмечено, остальные «уже сохранено как …» и не отмечены → импорт → подключение снова в своей папке, пароль пустой (подсказка в форме нет). Файл с битой записью — импортируются остальные, сообщение о пропущенных. Скопировать экспорт в `.vscode/datanest.json` — подключения появляются в узле проекта.

## 16. Импорт / экспорт и дампы (0.5.0)

1. Выполнение файла: в проводнике на `.sql`-файле — «Выполнить SQL-файл…» → выбор подключения и базы → окно «Выполнить «…» (размер) на «…»?» с кнопками «Остановиться на первой ошибке» / «Продолжать при ошибках». Уведомление показывает проценты, число запросов и ошибок; «Отмена» останавливает выполняемый запрос, сообщение «отменён после N запросов». Редакторы во время выполнения свободны.
2. Дамп `mysqldump` (с `DELIMITER` и `/*!40101 … */`) и `pg_dump --inserts` на 50+ МБ выполняются до конца, память расширения не растёт (Process Explorer). Дерево после выполнения показывает новые таблицы.
3. Файл с ошибкой в середине: «Остановиться» → красное сообщение «остановлен на строке N: …», остальное не выполнено; «Продолжать» → жёлтое сообщение с числом ошибок, «Показать отчёт» открывает Markdown со строками, текстами ошибок и началом запросов.
4. `pg_dump` без `--inserts` (с `COPY … FROM stdin`): в отчёте — «COPY … FROM stdin не поддерживается», данные блока пропущены, следующие запросы выполнились; `\restrict` — в «Пропущенных командах psql».
5. Read-only подключение — отказ до начала; production — в вопросе «PRODUCTION …». Файл, который заканчивается внутри `BEGIN` без `COMMIT`, — в отчёте «транзакция откачена», данных нет. В дереве: «Выполнить SQL-файл…» на подключении, базе и схеме выполняет на них; на вкладке открытого `.sql` — в контекстном меню вкладки.
6. Дамп: на базе MySQL «Дамп в SQL-файл…» → все галочки → «Структура и данные» → «Заменять существующее» → файл. Уведомление: таблица, число строк, «таблица N из M». Сообщение «Дамп сохранён: …» с «Открыть» / «Показать в папке». В файле нет `DEFINER=` и имени исходной базы. Выполнить его («Выполнить SQL-файл…») на пустой базе → те же таблицы, строки, представление, функция, процедура, триггер; выполнить второй раз — без ошибок.
7. Дамп PostgreSQL: на подключении → выбор базы и схемы; в файле `CREATE SCHEMA IF NOT EXISTS`, `CREATE TYPE … AS ENUM`, внешние ключи — `ALTER TABLE … ADD CONSTRAINT` после строк. На пустой базе выполняется; новая строка в таблице с `serial` получает следующий номер.
8. Выделить две таблицы (Ctrl) → «Дамп в SQL-файл…» → отмечены только они; «Только структура» — в файле нет `INSERT`; «Только данные» — нет `CREATE`. На папке «Таблицы» отмечены только таблицы; на ней же снова есть «Новая таблица…» и «+».
9. Отмена дампа большой таблицы → «Дамп отменён», файла нет, прежний файл с тем же именем (если был) не изменился. Под пользователем без прав на чужие процедуры MySQL — жёлтое сообщение «Пропущены — …», в файле комментарий `-- Skipped …`.
10. Импорт: на таблице «Импортировать данные из файла…» → CSV с `;` и строкой имён → разделитель «Точка с запятой» и галочка «Первая строка — имена колонок» выбраны сами; колонки сопоставлены по именам. Сменить разделитель на запятую → колонки перечитаны. Предпросмотр: неверная дата помечена красным с причиной, незаполняемые колонки — `DEFAULT`.
11. «Пропустить неподходящие строки» → «Импортировать» → прогресс, «Готово: импортировано N, пропущено M», список «Строка K, колонка X: …». «Всё или ничего» на том же файле → «Ничего не импортировано», таблица не изменилась. «Остановить» на большом файле работает. JSON-массив и JSON Lines импортируются; 20-значное число в `DECIMAL(30,0)` — без потери цифр.
12. После импорта в таблицу с `serial`/`AUTO_INCREMENT` новая строка без id получает следующий номер. Read-only подключение — отказ до выбора файла; production — вопрос перед стартом.
13. Экспорт: на таблице в дереве «Экспортировать данные…» → XLSX → файл открывается в Excel/LibreOffice, строк столько же, сколько в таблице; CSV и JSON большой таблицы (100 000+ строк) — прогресс, память расширения не растёт, «Отмена» не оставляет файла.
14. Табличный вид с фильтром и сортировкой, страница 2 → «Выгрузить как… CSV» → в файле все отфильтрованные строки в порядке сортировки, а не одна страница. `SELECT * FROM big_table` при лимите строк 1000 → «Выгрузить как…» → вопрос «Все строки / Только эти 1000 строк»; «Все строки» — 10 000 строк в файле. Для `INSERT … RETURNING` вопроса нет — пишутся загруженные строки.
15. Генератор: на таблице `customers` «Сгенерировать тестовые данные…» → `id` «нумерует база», `email` — «Email», `full_name` — «Имя и фамилия», `country` — «Страна»; предпросмотр правдоподобный. «Новое» зерно меняет строки, возврат к прежнему зерну — те же строки. Доля NULL 50% у `full_name` → примерно половина NULL в предпросмотре.
16. 1000 строк → «Вставить» → прогресс, «Готово: вставлено строк: 1000»; в таблице 1000 новых строк, email уникальны. Таблица с внешним ключом → значения только из связанной таблицы; пустая связанная таблица → красное «В связанной таблице нет строк…», «Вставить» недоступна. «Открыть как SQL» → редактор с `INSERT` на том же подключении, выполняется. Read-only — отказ; production — вопрос.
17. Перенос: на базе MySQL «Скопировать в другое подключение…» → все таблицы → PostgreSQL, база и схема → «Структура и данные» → «Заменить» → вопрос → прогресс → «Скопировано таблиц: N, строк: M». В PostgreSQL: те же строки, `tinyint(1)` стал `boolean`, внешние ключи работают, новая строка без id получает следующий номер. «Показать отчёт» перечисляет пропущенные умолчания и ключи.
18. PostgreSQL → MySQL и PostgreSQL → SQLite-файл; MySQL → MariaDB (типы как есть). «Только данные» в базу без таблиц — в отчёте «нет в целевой базе». «Добавить в неё строки» в существующую таблицу с другим набором колонок — строки в общих колонках, в отчёте лишние колонки. Цель read-only — отказ; production — вопрос с `PRODUCTION`. Отмена посреди большой таблицы — «Отменено».

Дерево: индексы `datanest-seed`, `logs-2026.10`, `products` с зелёным значком, числом документов (у `products` — 61, с вложенными) и размером; `.datanest-hidden` — только с `datanest.showSystemObjects`. `products` → поля с типами: `name` (text) → `keyword`, `maker` (object) → `country`, `name`; `reviews` (nested) → `stars`, `text`. «Копировать имя» на поле — путь `name.keyword`.
3. «Новый индекс…» на подключении: имя `Upper` — отказ при вводе; `items` с `{ "mappings": { "properties": { "n": { "type": "long" } } } }` — индекс появляется с полем `n`; ещё раз — `resource_already_exists_exception`. «Удалить индекс…» на `items` — вопрос и ввод имени. Подключение под `reader` — создание отказывает правами сервера; read-only подключение — отказ до сервера.
4. Запросы: «Новый запрос Elasticsearch» на `products` — документ с `GET /products/_search` и телом, над запросами «▶ Send». Ctrl+Enter — справа «Ответ: …»: статус 200, «найдено 31, показано 20», таблица `_index`, `_id`, `_score`, поля `_source`; `POST /products/_search` с `{ "query": { "ids": { "values": ["big"] } } }` — `stock` = `9007199254740993` и в таблице, и в «Ответ». `GET /products/_count` — «документов: 31»; `GET /_cat/indices?v` — текст как есть; `GET /nope/_search` — 404 и причина. Сломанный JSON в теле — «строка:столбец …». `POST /_bulk` с парами строк — `"errors": false`.
5. Политика: production — вопрос перед `PUT`/`POST /x/_doc`; `DELETE /items` и `_delete_by_query` с `match_all` — вопрос safe mode (с `block` — отказ); read-only — `PUT` отказывает до отправки, `_search` работает.
