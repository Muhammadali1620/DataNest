# Ручной тест-план

Прогоняется перед каждым релизом в трёх редакторах: **VS Code**, **VSCodium**, **Cursor**.
Автотесты (`npm test`, `npm run test:integration`, `npm run test:e2e`) должны быть зелёными до начала.

Отметки: `✅` работает · `⚠️` работает с замечанием · `❌` сломано (баг + тест по правилу 7 из ARCHITECTURE §11).

## Подготовка

```sh
npm ci
npm run db:up          # MySQL 7306, MariaDB 7307, PostgreSQL 7432
npm run package        # соберёт datanest-<версия>.vsix
```

Поставить `.vsix` в каждый редактор: «Extensions: Install from VSIX…».
Перед прогоном в новом редакторе удалить прежнюю версию и перезапустить его.

Подключения для прогона (пароль у всех `datanest`, пользователь `datanest`, база `datanest_test`):

- MySQL — `127.0.0.1:7306`
- MariaDB — `127.0.0.1:7307`
- PostgreSQL — `127.0.0.1:7432`
- SQLite — новый файл через «Новый файл…» в форме

## 1. Активация

1. Открыть редактор без единого подключения → иконка DataNest есть в Activity Bar.
2. Открыть вид DataNest → видно приглашение создать подключение, расширение активировалось (в «Output → DataNest» строка `DataNest 0.1.0 activated`).
3. Команда «DataNest: Show Logs» открывает канал.
4. В палитре нет служебных команд: «Open Ping Page», «Run This Statement», «Open Table».

## 2. Подключения

1. «New Connection» → форма открылась вкладкой.
2. Тип MySQL: порт подставился 3306, сменить на 7306, заполнить хост/пользователя/пароль/базу.
3. «Проверить подключение» → «Подключение работает».
4. Ввести неверный пароль → «Проверить подключение» показывает сообщение сервера, а не стек.
5. Сохранить → подключение появилось в дереве.
6. Повторить для MariaDB и PostgreSQL.
7. SQLite: выбрать тип → поля хоста/порта исчезли, появился выбор файла. «Новый файл…» → сохранить `~/datanest-demo.db` → сохранить подключение.
8. Изменить подключение: открыть форму, увидеть подсказку «Пароль сохранён», сохранить без ввода пароля → подключение по-прежнему работает.
9. Дублировать подключение → копия с именем «… (copy)» и рабочим паролем.
10. Удалить копию → подтверждение, затем исчезает из дерева.
11. Перезапустить редактор → подключения на месте, пароли не потерялись.

## 3. Дерево

1. Раскрыть MySQL → подключение стало зелёным, видны базы `datanest_test` и `datanest_empty`.
2. Системных баз (`information_schema`, `mysql`, `performance_schema`, `sys`) не видно.
3. Включить `datanest.showSystemObjects` → они появились без переподключения; выключить обратно.
4. `datanest_test` → «Таблицы» и «Представления»; в таблицах — `customers`, `orders`, `big_table`, в представлениях — `order_totals`.
5. Раскрыть `customers` → колонки с типом, `PK` у `id`, `NOT NULL` где положено, `DEFAULT` у `created_at`.
6. PostgreSQL: база → схемы (`public` сверху), `pg_catalog` и `information_schema` скрыты.
7. SQLite: под подключением сразу «Таблицы»/«Представления», без уровня баз.
8. «Копировать имя» на таблице и на колонке → в буфере имя.
9. «Обновить» на подключении → дерево перечитывается (создать таблицу в `psql` и убедиться, что она появилась только после «Обновить»).
10. «Отключиться» → значок погас, при следующем раскрытии подключается снова.
11. Остановить Docker (`npm run db:down`) и раскрыть узел → ошибка показана листом, дерево не сломано. Поднять обратно (`npm run db:up`).

## 4. Редактор SQL

1. «Новый запрос» из заголовка вида → пустая вкладка SQL, в статус-баре «Выбрать подключение».
2. Выбрать подключение и базу → в статус-баре имя и база.
3. «Новый запрос» из контекстного меню базы → документ сразу привязан к ней.
4. Набрать `SEL` → автодополнение предлагает `SELECT`.
5. `SELECT * FROM ` → предлагаются таблицы; `SELECT c. FROM customers c` → предлагаются колонки.
6. Внутри строки `'…'` и после `--` подсказок нет.
7. Над каждым запросом есть «▶ Run».
8. `Ctrl+Enter` на запросе под курсором → выполняется только он.
9. Выделить два запроса → `Ctrl+Enter` выполняет оба (две вкладки результатов).
10. `Ctrl+Shift+Enter` → выполняется весь файл.
11. Скрипт с `DELIMITER //` и процедурой выполняется целиком, тело не разрезано.
12. PostgreSQL: функция с телом `$$ … $$` выполняется целиком.

## 5. Выполнение и отмена

1. `SELECT SLEEP(10)` (MySQL) → в статус-баре счётчик времени, в заголовке редактора кнопка «Отменить».
2. Нажать «Отменить» → запрос останавливается за секунду-две, редактор снова свободен.
3. Отменить из панели результатов кнопкой «Отменить» → тот же результат.
4. Поставить `datanest.queryTimeout` = 3, выполнить `SELECT SLEEP(10)` → через 3 с результат с ошибкой «timeout» и упоминанием настройки. Вернуть 0.
5. `SELECTT 1` → ошибка с текстом сервера, «на символе N» и ссылкой «Перейти к ошибке» — курсор встаёт на место ошибки.
6. Скрипт из трёх запросов, где второй с ошибкой → первая вкладка с данными, вторая с ошибкой, третий не выполнялся.
7. `INSERT`/`UPDATE`/`DELETE` во временную таблицу → «затронуто строк».

## 6. Таблица результатов

1. `SELECT * FROM big_table` (10 000 строк) → при лимите 1000 видно предупреждение об обрезке.
2. Поставить `datanest.rowLimit` = 10000, выполнить снова → прокрутка до конца плавная, редактор не подвисает.
3. Заголовок и номера строк остаются на месте при прокрутке вниз и вправо.
4. Потянуть границу колонки → ширина меняется за указателем; двойной клик по границе — подгон по заголовку.
5. `NULL` отличается от строки `NULL` (курсив, серый).
6. Клик по ячейке, протягивание мышью, `Shift+стрелки`, `Ctrl+A` → выделение ведёт себя ожидаемо.
7. `Ctrl+C` на диапазоне → вставить в LibreOffice Calc / Excel / Google Sheets: столбцы и строки не разъехались, значение с переводом строки осталось в одной ячейке.
8. Клик по заголовку: по возрастанию → по убыванию → исходный порядок. `NULL` всегда в конце.
9. Поиск: ввести `example.com` → «1 из N», Enter и Shift+Enter ходят по совпадениям, найденная строка выделяется и прокручивается.
10. Несколько запросов → переключение вкладок сохраняет содержимое каждой.
11. CSV: кнопка «CSV» → сохранить файл → открыть: заголовок на месте, значения с запятыми и кавычками корректны, `BIGINT` не округлён.
12. JSON: кнопка «JSON» → в файле массив объектов, точные числа строками, JSON-колонка вложена как объект.

## 7. Просмотр таблицы

1. Контекстное меню таблицы → «Открыть таблицу» → страница данных и «строки 1–200 из N».
2. «Вперёд»/«Назад» листают, диапазон меняется, на последней странице «Вперёд» недоступно.
3. Изменить `datanest.pageSize` на 50 → открыть таблицу заново → страницы по 50.
4. Открыть представление `order_totals` → данные показаны так же.
5. Открыть пустую таблицу → «строки 0–0 из 0», без ошибок.

## 8. Темы, язык, доступность

1. Переключить светлую/тёмную/высококонтрастную тему → дерево, форма и таблица читаются, цвета берутся из темы.
2. Переключить язык редактора на русский (`Configure Display Language`) → интерфейс расширения на русском.
3. Пройти форму подключения только с клавиатуры (Tab/Shift+Tab/Enter).
4. В таблице: Tab до таблицы, стрелки, `Ctrl+Home`/`Ctrl+End`, `PageUp`/`PageDown`.

## 10. Завершение

1. Закрыть все вкладки → в «Output → DataNest» нет ошибок.
2. Закрыть редактор → процесс завершается без зависших соединений (`npm run db:logs` не показывает активных сессий DataNest).
3. `npm run db:down`.
